# Direct Eval over caller bindings

Integrated base: bc02f7960e5e0551092cfd342375c21f4bf0c820 (includes source Document and activation-local Execute cache).

Before this change direct Eval/Вычислить called the runtime marker, which requires an interpreter evaluation frame and raises instead of evaluating. Static calls using either built-in name now bind an expression evaluator only for the canonical registered marker. Custom overrides retain their ordinary service calls. Arguments, service policy, lifecycle checks and mutation of the bound implementation remain checked. Host-created aliases of the canonical Eval marker are not supplied caller lexical bindings in this slice.

The evaluator parses exactly one complete expression before executing any expression effects and admits its constructors and calls. It compiles directly to Python and uses live caller addresses through FragmentScope, with no VM dispatch, locals copy/flush or persistent preparation cache. Each invocation gets a fresh scope, which closes even on failure. Source length (65536) and shared nesting depth (16), including dual/server calls, remain bounded. Existing ErrorDescription state is shared so nested handlers invalidate stale outer diagnostics. Unsupported syntax/constructors remain nonrecoverable admission failures; existing source/SQLite/security boundaries are retained. ErrorInfo service support is outside this slice.
