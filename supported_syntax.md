# Поддерживаемые объекты и функции

Текущий справочник встроенных типов, коллекций и глобальных функций Yadinassi.
Он описывает доступное подмножество API, а не полную совместимость с платформой
1С. Базовый синтаксис и устройство примитивных типов здесь не рассматриваются.
История расширения возможностей и примеры находятся в [features.md](features.md),
неподдерживаемые объекты — в [unsupported_syntax.md](unsupported_syntax.md).

Русские и английские имена ниже равноправны и нечувствительны к регистру.
В сигнатурах квадратные скобки обозначают необязательные аргументы, а `...` —
повторяющиеся аргументы. Это обозначения справочника, не текст программы.
Перечислены встроенные возможности обычного интерпретатора; объекты и функции,
добавленные приложением через Python API, в этот список не входят.

## Профиль условной компиляции

Публичный профиль `standalone` применяется по умолчанию и явно
через `Interpreter(compilation_profile="standalone")`, `parse(..., compilation_profile="standalone")`
или CLI `--preprocessor-profile standalone` во всех режимах ввода.
Прежние флаги `Client` / `Server` / `AtClient` / `AtServer` и их русские
псевдонимы сохраняют значения для клиента, сервера, NoContext и dual-тел.
Дополнительно распознаются пять всегда ложных в этом профиле символов:
`ThinClient` / `ТонкийКлиент`, `WebClient` / `ВебКлиент`,
`ThickClientOrdinaryApplication` / `ТолстыйКлиентОбычноеПриложение`,
`ThickClientManagedApplication` / `ТолстыйКлиентУправляемоеПриложение`,
`ExternalConnection` / `ВнешнееСоединение`. Регистр не важен.
Профиль наследуется импортами и серверными активациями, не выбирается ОС
и не меняет `native_target`, включая Windows-умолчание. Это автономная
политика компиляции, не поддержка исполнения этих режимов платформы.
Отдельный профиль `managed-thick-file` выбирается только явно теми же API
или CLI `--preprocessor-profile managed-thick-file`. Во всех пяти местах
компиляции он делает истинными `Client`, `Server` и
`ThickClientManagedApplication`. `AtClient` истинен только на клиенте,
`AtServer` только на контекстном сервере; оба ложны в NoContext/dual.
Остальные четыре application-символа ложны. Русские псевдонимы равноправны.
Это ограниченная измеренная таблица managed thick file на Linux 8.3.27.1508,
не UI/клиентская эмуляция и не Windows native parity. Профиль меняет только
выбор исходного кода при компиляции: dispatch, логический `execution_context`,
доступность builtins, необязательный `database_context` и `native_target`
остаются независимыми. Корневой модуль по-прежнему исполняется на клиенте.
Точные таблицы и ограничения приведены в [features.md](features.md).

## Собственный модуль / ThisObject

`ЭтотОбъект` / `ThisObject` — ограниченный приемник текущего автономного модуля,
а не универсальный объект платформы. После завершения инициализации он открывает
только явно экспортные переменные и поддержанные подпрограммы. Dual NoContext
не открывается через module receiver даже при Export; вызов через файловый import
тоже пока вне этого ограниченного subset. Неявный ThisObject недоступен в
NoContext/dual NoContext, если имя не затенено явно. Переменная, объявленная через
`Перем Имя Экспорт` / `Var Name Export`, читается и меняется через свойство с тем
же именем; ссылка на свойство остается живой при передаче в подпрограмму.
Публичный доступ во время инициализации, закрытые/неизвестные члены и рефлексия
отклоняются. Не затененное явно имя приемника недоступно для присваивания.

Платформенные методы, строковое/типовое представление и сериализация самого
приемника не поддержаны. Существующий файловый импорт — расширение yadinassi;
его кэш и правила имен не изменены. Подробности, пример общего состояния и
границы контекста находятся в [features.md](features.md#экспортные-переменные-и-собственный-модуль).

## Коллекции

### Массив / Array

Конструкторы: `Массив()`, `Массив(Размер [, Размер2, ...])`,
`Массив(ФиксированныйМассив)`.

- Чтение и запись по индексу, обход элементов. Индексы начинаются с нуля.
- `Количество / Count()`, `ВГраница / UBound()`, `Получить / Get(Индекс)`,
  `Найти / Find(Значение)`.
- `Добавить / Add([Значение])`, `Вставить / Insert(Индекс [, Значение])`,
  `Установить / Set(Индекс, Значение)`, `Удалить / Delete(Индекс)`,
  `Очистить / Clear()`.
- Пропущенное значение при добавлении или вставке — `Неопределено`.
  Вставка за текущей границей дополняет промежуток `Неопределено`.
  Чтение, запись и `Удалить / Delete` требуют существующего индекса.
  Удаление из пустого массива или выше `ВГраница()` вызывает ошибку,
  не меняя содержимое (нативный результат 1С 8.3.27.2342, Windows, ru-RU).
  Отрицательные, дробные и нечисловые индексы также отклоняются.
- `ВГраница()` пустого массива возвращает `-1`, неудачный поиск — `Неопределено`.
- Многомерный массив состоит из отдельных вложенных массивов. Размеры целые,
  неотрицательные; при нескольких измерениях все размеры должны быть положительными.
  Лимиты конструктора Yadinassi: 64 измерения и суммарно 1 000 000 ячеек
  и вложенных массивов. Рост за одну вставку ограничен 1 000 000 элементов.
- Копирование из фиксированного массива рекурсивно преобразует непосредственно
  вложенные фиксированные массивы в изменяемые; другие значения сохраняют ссылки.

### ФиксированныйМассив / FixedArray

Конструктор: `ФиксированныйМассив(Массив)`.

- Чтение по индексу, обход, `Количество / Count()`, `ВГраница / UBound()`,
  `Получить / Get(Индекс)`, `Найти / Find(Значение)`.
- Запись элементов и изменяющие методы отсутствуют.
- Непосредственно вложенные изменяемые массивы также преобразуются в фиксированные.
  Структуры, соответствия и уже фиксированные массивы сохраняют ссылки:
  это не универсальная глубокая заморозка графа объектов.
  Циклы из непосредственно вложенных изменяемых массивов отклоняются.

### Структура / Structure

Конструкторы: `Структура()`, `Структура(ИменаСвойств [, Значения...])`,
`Структура(ФиксированнаяСтруктура)`.

- Имена в конструкторе разделяются запятыми; отсутствующие значения — `Неопределено`.
- Чтение и запись существующего свойства через точку или индекс с именем свойства.
  Имена свойств нечувствительны к регистру и должны быть допустимыми идентификаторами.
- `Количество / Count()`, `Свойство / Property(Имя [, Значение])`.
  `Свойство` возвращает признак наличия и может записать найденное значение
  во второй аргумент; для отсутствующего свойства записывает `Неопределено`.
- `Вставить / Insert(Имя [, Значение])`, `Удалить / Delete(Имя)`, `Очистить / Clear()`.
  Вставка создает или заменяет свойство. Удаление отсутствующего свойства допустимо.
- Обход дает пары `КлючИЗначение`. Изменение состава структуры во время обхода
  не поддерживается; замена значений существующих свойств не меняет состав.

### ФиксированнаяСтруктура / FixedStructure

Конструкторы: `ФиксированнаяСтруктура()`,
`ФиксированнаяСтруктура(ИменаСвойств [, Значения...])`,
`ФиксированнаяСтруктура(Структура)`.

- Чтение свойств через точку или индекс, обход пар `КлючИЗначение`,
  `Количество / Count()`, `Свойство / Property(Имя [, Значение])`.
- Свойства недоступны для записи, изменяющие методы отсутствуют.
  Состав копируется, вложенные значения сохраняют ссылки.

### Соответствие / Map

Конструкторы: `Соответствие()`, `Соответствие(ФиксированноеСоответствие)`.

- Чтение и запись по ключу, обход пар `КлючИЗначение`.
- `Количество / Count()`, `Получить / Get(Ключ)`,
  `Вставить / Insert(Ключ [, Значение])`, `Удалить / Delete(Ключ)`, `Очистить / Clear()`.
- Отсутствующий ключ при чтении дает `Неопределено`; запись создает или заменяет
  элемент, удаление отсутствующего ключа допустимо.
- Тип ключа значим; ключи-коллекции сопоставляются по идентичности объекта.
  Порядок обхода не является гарантией совместимости с 1С.
  Изменение состава при обходе не поддерживается.

### ФиксированноеСоответствие / FixedMap

Конструктор: `ФиксированноеСоответствие(Соответствие)`.

- Чтение по ключу, обход пар `КлючИЗначение`, `Количество / Count()`,
  `Получить / Get(Ключ)`.
- `Получить` отсутствующего ключа возвращает `Неопределено`, но индексное чтение
  отсутствующего ключа вызывает ошибку.
- Запись элементов и изменяющие методы отсутствуют.
  Состав копируется, вложенные значения сохраняют ссылки.

### СписокЗначений / ValueList

Конструктор: `СписокЗначений()` без аргументов. Чтение по числовому индексу,
`Получить / Get(Индекс)` и обход возвращают живые `ЭлементСпискаЗначений /
ValueListItem`. Отдельного конструктора элемента и замены элемента присваиванием
по индексу нет.

- `Количество / Count()`, `Индекс / IndexOf(Элемент)`.
- `Добавить / Add([Значение [, Представление [, Пометка]]])`,
  `Вставить / Insert(Индекс [, Значение [, Представление [, Пометка]]])`.
  Оба метода возвращают добавленный элемент; умолчания — `Неопределено`,
  пустая строка и `Ложь`. Пропуски необязательных позиций поддержаны для
  именованной переменной списка; вычисляемый приемник с пропусками отклоняется.
- `Удалить / Delete(ИндексИлиЭлемент)`, `Очистить / Clear()`,
  `Сдвинуть / Move(ИндексИлиЭлемент, Смещение)`,
  `ЗаполнитьПометки / FillChecks(Пометка)`.
- `СортироватьПоЗначению / SortByValue([Направление])`,
  `СортироватьПоПредставлению / SortByPresentation([Направление])`.
  Направление: `НаправлениеСортировки.Возр / SortDirection.Asc` либо
  `НаправлениеСортировки.Убыв / SortDirection.Desc`; умолчание/Неопределено — Возр.
  Сохраняются элементы, ID и поля; неподтвержденные типы, смеси и текст отклоняются.
  У значения регистр/концевые ASCII-пробелы незначимы, у представления значимы.
  Границы сортировки и нового перечисления: [features.md](features.md#сортировка-списка-значений-и-направлениесортировки).
- `НайтиПоЗначению / FindByValue(Значение)`,
  `НайтиПоИдентификатору / FindByID(Идентификатор)`.
  Поиск возвращает живой элемент или `Неопределено`; поиск по значению выбирает
  первое совпадение. Чужой или удаленный элемент дает `-1` в `IndexOf`.
- `Скопировать / Copy()` создает независимые элементы с общими вложенными
  значениями, сохраняя текущий порядок, значения, представления и пометки.
  Поддержаны списки после сортировки, удаления/перемещения и очистки, в том числе
  с повторным заполнением. Копия получает новые ID от `0` до `Count() - 1`,
  следующий ID равен `Count()`; ID и история выделения исходного списка не меняются.
- `ЗагрузитьЗначения / LoadValues(Массив)` заменяет элементы значениями массива
  с пустыми представлениями и снятыми пометками; `ФиксированныйМассив` не принимается.
  `ВыгрузитьЗначения / UnloadValues()` возвращает новый массив значений.
- `ТипЗначения / ValueType` и `ДоступныеЗначения / AvailableValues` доступны только
  для чтения: соответственно пустое `ОписаниеТипов` и `Неопределено`.

Элемент: изменяемые `Значение / Value`, `Представление / Presentation`,
`Пометка / Check`, метод `ПолучитьИдентификатор / GetID()`.
Три изменяемых поля можно передавать по ссылке в пользовательские процедуры и
функции: запись и обратное чтение видны немедленно, `Знач / Val` сохраняет
переданное значение. Приемник вычисляется один раз; перестановка и удаление
элемента не перенаправляют ссылку, пока исходный список существует. Преобразования
поля и кэш строки остаются такими же, как при прямом присваивании. Нативное
подтверждение этого шага: Linux 8.3.27.1508; отдельно восстановленные элементы
и ссылки после освобождения списка пока отклоняются.
Идентификатор сохраняется при перестановке; после удаления или очистки сохраненный
элемент допускает чтение/запись полей, но его ID равен `-1`. Новые ID не переиспользуют
удаленные. Границы преобразований, перемещения чужого элемента, строкового
представления и ресурсные лимиты описаны в [features.md](features.md).

### ТаблицаЗначений / ValueTable

Конструктор: `ТаблицаЗначений()` без аргументов. Свойство только для чтения
`Колонки / Columns` возвращает `КоллекцияКолонокТаблицыЗначений /
ValueTableColumnCollection`. Обход таблицы дает `СтрокаТаблицыЗначений /
ValueTableRow`, обход колонок — `КолонкаТаблицыЗначений / ValueTableColumn`.
Отдельных конструкторов для этих трех объектов нет.

- `Количество / Count()`, `Получить / Get(Индекс)`, `Индекс / IndexOf(Строка)`.
- `Добавить / Add()`, `Вставить / Insert(Индекс)`,
  `Удалить / Delete(ИндексИлиСтрока)`, `Очистить / Clear()`,
  `Сдвинуть / Move(ИндексИлиСтрока, Смещение)`.
- `Найти / Find(Значение [, Колонки])`, `НайтиСтроки / FindRows(СтруктураОтбора)`.
- `Скопировать / Copy([СтрокиИлиОтбор [, Колонки]])`,
  `СкопироватьКолонки / CopyColumns([Колонки])`.
  Отбор — структура; массив строк сохраняет порядок и повторы.
  Чужие строки допустимы только при той же схеме имен и типов колонок.
- `ЗаполнитьЗначения / FillValues(Значение [, Колонки])`,
  `ЗагрузитьКолонку / LoadColumn(Массив, Колонка)`,
  `ВыгрузитьКолонку / UnloadColumn(Колонка)`, `Итог / Total(ИмяКолонки)`.
  Для загрузки/выгрузки колонка задается именем, индексом или ее объектом;
  `Итог` принимает только имя. Список колонок — строкой
  имен через запятую, без пустых элементов и пробелов. Пустая строка означает все.

Коллекция колонок:

- `Количество / Count()`, `Получить / Get(Индекс)`, `Индекс / IndexOf(Колонка)`,
  `Найти / Find(Имя)`.
- `Добавить / Add([Имя [, ТипЗначения [, Заголовок [, Ширина]]]])`,
  `Вставить / Insert(Индекс [, Имя [, ТипЗначения [, Заголовок [, Ширина]]]])`.
- `Удалить / Delete(ИмяИндексИлиКолонка)`, `Очистить / Clear()`,
  `Сдвинуть / Move(ИндексИлиКолонка, Смещение)`.
- У колонки изменяемые `Имя / Name`, `Заголовок / Title`, `Ширина / Width`;
  `ТипЗначения / ValueType` — только для чтения, значение `ОписаниеТипов`.

Строка: `Получить / Get(Индекс)`, `Установить / Set(Индекс, Значение)`,
`Владелец / Owner()`, обход ячеек. Свойства строки и ее индексатор по имени
дают ячейки без учета регистра. Индексаторы строк и колонок также принимают
числовой индекс; методы `Get/Set` принимают только числовой индекс.
Заменить строку в таблице или колонку в коллекции присваиванием нельзя.
Имена методов и одноименных колонок разделены.

Индексы начинаются с нуля и усекают дробь. Вставка вне диапазона добавляет
в конец; перемещение за границы вызывает ошибку. Последняя удаленная колонка
очищает строки. Поиск возвращает живые строки; копия имеет независимую схему
и строки, но общие вложенные значения. Пустой отбор `FindRows` дает пустой массив.
Типизированные умолчания/преобразования, особые результаты `Total`, удаленные
ссылки и точные ресурсные границы описаны в [features.md](features.md).

Пропуски позиций аргументов у `Add/Insert` колонок и `Copy` таблицы поддержаны
для именованной переменной или прямого `Таблица.Колонки`/`Table.Columns`.
Вычисляемые приемники с пропусками отклоняются до исполнения.
Сортировка `Сортировать / Sort` и группировка `Свернуть / GroupBy` поддержаны
в пределах, описанных в [features.md](features.md). Интерфейсный выбор строки отсутствует.

`Индексы / Indexes` — доступная только для чтения коллекция индексов таблицы.
`ИндексыКоллекции / CollectionIndexes` поддерживает `Добавить / Add([Колонки])`,
`Удалить / Delete(НомерИлиИндекс)`, `Очистить / Clear()`, `Количество / Count()`,
числовой индексатор и обход. `ИндексКоллекции / CollectionIndex` поддерживает
числовой индексатор и обход имен колонок; его элементы доступны только для чтения.
Конструкторов этих типов, методов `Get` коллекции и `Count` индекса нет.
Повторяющиеся колонки/индексы допустимы; пустой список создает пустой индекс.
Точные наблюдения поиска, жизненного цикла и ресурсные границы — в [features.md](features.md).

## Служебные типы и системные перечисления

- `КлючИЗначение / KeyAndValue`: элемент обхода структуры или соответствия.
  Свойства `Ключ / Key` и `Значение / Value` доступны только для чтения.
  Конструктора `Новый КлючИЗначение` нет.
- `Тип / Type`: непрозрачное значение, получаемое через `Тип(Имя)` или
  `ТипЗнч(Значение)`. Поддержаны сравнение и использование как ключа соответствия.
  Это не описание метаданных и не `ОписаниеТипов`; конструктора `Новый Тип` нет.
- `РежимОкругления / RoundMode`: глобальное пространство значений
  `Окр15как10 / Round15as10` и `Окр15как20 / Round15as20`, доступных только для чтения.
  Тип отдельного значения — `РежимОкругления / RoundMode`, тип самого пространства —
  `ПеречислениеРежимОкругления / EnumRoundMode`. Обход пространства дает два значения
  в указанном порядке. Отдельных конструкторов для них нет.
- `Символы / Chars`: закрытое пространство строковых констант только для чтения.
  `ВК/CR` = U+000D, `ВТаб/VTab` = U+000B, `НПП/NBSp` = U+00A0,
  `ПС/LF` = U+000A, `ПФ/FF` = U+000C, `Таб/Tab` = U+0009.
  Имена пространства и свойств регистронезависимы; значения являются обычными
  строками длины 1, поддерживают существующие строковые операции и кодеки.
  Индексный доступ по строковому имени, например `Chars["lf"]`, использует
  тот же закрытый регистронезависимый набор. Запись свойства/индекса, неизвестный
  ключ и числовой индекс вызывают перехватываемую ошибку.
  Объявленные переменные, параметры, подпрограммы и внедрённые функции сохраняют
  обычный приоритет над глобальным пространством. Конструктор, перечисление,
  тип/представление/кодек самого пространства не добавляются.
  Значения и прямой доступ подтверждены на Linux 1С 8.3.27.1508 в серверном и
  настоящем управляемом клиентском контекстах (PR80, run39743653257; индексы run39746207974);
  свежий Windows-прогон для этих констант не заявляется.
- `НаправлениеПоиска / SearchDirection`: глобальное пространство значений
  `СНачала / FromBegin` и `СКонца / FromEnd`, доступных только для чтения.
  Обход дает эти два значения в указанном порядке; их строковые представления —
  `С начала` и `С конца`. Значения различаются, не равны числам или значениям
  другого перечисления и могут быть ключами соответствия. Конструкторов нет.
  `Тип("НаправлениеПоиска")` и `Type("SearchDirection")` дают тип значения.
  Тип самого пространства получается через `ТипЗнч(НаправлениеПоиска)`;
  его строковое представление — `ПеречислениеНаправлениеПоиска`.
  Поиск типа по именам `ПеречислениеНаправлениеПоиска` / `EnumSearchDirection`
  отклоняется, хотя значение типа пространства поддержано внутренним кодеком.

- `НаправлениеСортировки / SortDirection`: глобальное пространство значений
  `Возр / Asc` и `Убыв / Desc` только для чтения; обход дает их в этом порядке.
  Представления значений: `По возрастанию` и `По убыванию`; они не являются
  числами 0/1. `Тип("НаправлениеСортировки")` / `Type("SortDirection")` и
  TypeOf значений поддержаны. Представление пространства:
  `ПеречислениеНаправлениеСортировки`; его TypeOf и кодек пока не поддержаны.
  Конструктора, индексного доступа и изменяемых свойств нет.

Специальное значение `Null` поддержано отдельно от `Неопределено`.
`Тип("Null")`, `ТипЗнч(Null)` / `TypeOf(Null)` дают его тип;
`Строка(Null)` дает пустую строку, `ЗначениеЗаполнено(Null)` — `Ложь`.
`Null` равен самому себе и отличается от `Неопределено`, чисел и строк;
его можно хранить в коллекциях и использовать как отдельный ключ соответствия.
Числовое/булево преобразование, порядок, числовая арифметика и непосредственное условие
для `Null` отклоняются. Обычное короткое вычисление `И / ИЛИ` сохраняется.
Это автономное специальное значение; поддержка запросов или SQL-логики из этого
не следует. Конструктора и объектного API у него нет.

Наличие типа не означает, что каждая глобальная функция принимает его.
Ограничения отдельных функций приведены ниже.

## Глобальные функции и процедуры

### Необязательный контекст файловой базы

- `СтрокаСоединенияИнформационнойБазы()` / `InfoBaseConnectionString()` —
  нулевой по арности вызов, возвращающий `File="каталог";` для явно заданного
  `--f DIRECTORY` или `Interpreter(database_context=FileDBContext(directory))`.
  Относительный путь привязывается лексически к рабочему каталогу создания
  контекста, не к каталогу BSL-файла; пробелы и Unicode сохраняются. Пустой
  аргумент CLI `--f ""` / `--f=` отклоняется с кодом `2` до создания контекста.
- Только фактическое исполнение вызова read-only проверяет ограниченный
  заголовок и геометрию `1Cv8.1CD`. Без контекста ошибка
  `db required for further code execution` перехватывается `Попытка/Исключение`.
  Неподдержанный путь или нераспознанный заголовок также дают catchable error,
  не запрещая остальной автономный код заранее.
- Контекст передается импортам и поддержанным переходам client/server;
  `AtClient` и Windows-профиль совместимости по умолчанию не изменены.
  Это не сеанс, аутентификация, запросы, метаданные или проверка валидности базы.
  [Границы путей, Python API и native evidence](docs/file-database-context.md).

Отдельные низкоуровневые Python API хранения не расширяют этот BSL-синтаксис:
экспериментальный `filedb_named_file.read_dbnames` извлекает только байты
PARAMS/DBNames по явному ограниченному профилю, без чтения логических метаданных,
запросов или подкоманд CF/DT. [Границы API](docs/file-db-named-file-transport.md).

### Типы, значения и диагностика

- `Тип / Type(Имя)`, `ТипЗнч / TypeOf(Значение)` — для перечисленных выше встроенных
  типов, а также примитивных значений интерпретатора. Исключение поиска по имени —
  тип пространства `НаправлениеПоиска`, описанный выше. TypeOf пространства
  `НаправлениеСортировки` пока не поддержан. Неизвестные типы отклоняются;
  эти функции не открывают доступ к отсутствующим объектам платформы.
- `Строка / String(Значение)`, `Число / Number(Значение)`,
  `Булево / Boolean(Значение)` — встроенные преобразования.
- `ЗначениеЗаполнено / ValueIsFilled(Значение)` — для примитивных значений и шести
  коллекций выше. Для коллекций проверяет непустой состав; для `Тип`,
  `КлючИЗначение`, значений и пространств системных перечислений пока не поддерживается.
- `ЗаполнитьЗначенияСвойств / FillPropertyValues(Приемник, Источник
  [, СписокСвойств, ИсключаемыеСвойства])` — процедура только для структур
  и фиксированных структур. Копирует значения, не добавляя свойства приемника.
  Списки заполнения и исключения нельзя применять одновременно; в списках
  не поддержаны пустые имена и окружающие пробелы. Фиксированный приемник без
  списков остается неизменным, со списками отклоняется.
  Для target `linux-8.3.27.1508`, только между изменяемыми структурами, измеренный
  случай одного свойства источника, отсутствующего в приемнике и ровно один раз
  указанного в EXCLUDE, сохраняет предшествующие общие неисключенные записи
  до ошибки на позиции этого свойства в источнике. Других свойств только
  источника в этом вызове быть не должно. Отсутствие имени в источнике,
  дубликат отсутствующего имени, смешанные невалидные списки, фиксированный
  источник и Windows/default сохраняют предварительный отказ без записей.
  [Точные native-наблюдения и ограничения PR87](docs/native-testing.md#deferred-pr87-exclude-compatibility-measurement).
- `Сообщить / Message(Значение)` — вывод одного значения.
- `ОписаниеОшибки / ErrorDescription()` — описание обрабатываемой ошибки,
  вне обработчика — пустой результат.
- `Вычислить / Eval(Выражение)` — вычисление одного выражения в текущем контексте.
  Принимает текст или конечное число; пределы Yadinassi: 65 536 символов
  и 16 вложенных вызовов. Не заменяет отсутствующие типы и функции платформы.

### Дата / Date и компоненты

- `Дата / Date(Строка)`, `Дата / Date(Год, Месяц, День)`,
  `Дата / Date(Год, Месяц, День, Час, Минута, Секунда)`.
  Строка — 8 или 14 ASCII-цифр канонической даты; локализованный разбор,
  другие длины, 4/5 аргументов и пропущенные компоненты не поддержаны.
  Компоненты принимают только числа; дробная секунда усекается,
  остальные дробные компоненты пока отклоняются. `Новый Дата` не предоставляется.
- `Год / Year(Дата)`, `Месяц / Month(Дата)`, `День / Day(Дата)`,
  `Час / Hour(Дата)`, `Минута / Minute(Дата)`, `Секунда / Second(Дата)`.
  Извлечение компонента не принимает строки и числовые заменители даты.
- Тип `Дата / Date` доступен через `Тип` и `ТипЗнч`, во внутреннем кодеке
  и как ключ коллекций. Обычные даты сравниваются по значению с точностью 0,1 мс.
  `Строка` использует зафиксированное представление ru-RU; `ЗначениеЗаполнено`
  отличает начало отсчета от остальных поддержанных дат.
- Арифметика поддерживает дату слева и числовое смещение в секундах;
  разность двух дат — число секунд. Смещение округляется к 0,1 мс,
  точная половина — от нуля. Обратное сложение числа и даты не поддерживается.
- Поддержанный диапазон заканчивается целой секундой `31.12.9999 23:59:59`:
  дробная часть последней секунды пока исключена. При выходе за диапазон
  на целую секунду известно только скалярное внутреннее представление результата.
  Для такого результата доступны `ТипЗнч` и прямая скалярная сериализация;
  сравнение, ключи, вложенная сериализация, строка, заполненность, компоненты
  и дальнейшая арифметика отклоняются. Более далекие или дробные выходы за границу
  не поддерживаются. Это ограничение реализации, а не утверждение о насыщении
  нативного значения до крайнего тика.
- Защитные пределы: 4096 цифр компонента/масштабированного смещения и 4096 символов
  литерала. Эти пределы не заявляются ограничениями платформы 1С.

### Системные часы

- `ТекущаяДата / CurrentDate()` — текущая дата и время компьютера,
  на котором выполняется процесс Yadinassi, в его локальном часовом поясе.
- `ТекущаяУниверсальнаяДата / CurrentUniversalDate()` — текущая дата и время UTC.
- `ТекущаяУниверсальнаяДатаВМиллисекундах / CurrentUniversalDateInMilliseconds()` —
  число миллисекунд UTC от `0001-01-01 00:00:00`, а не от начала Unix-времени.

Все три функции не имеют параметров и читают системные настенные часы заново
при каждом вызове. Это не монотонный таймер: коррекция часов может уменьшить
следующее значение. Вызовы не образуют общий атомарный снимок.

Без настройки локальная дата использует часовой пояс и правила перехода
на летнее время операционной системы процесса. Необязательная переменная
окружения `YADINASSI_TIMEZONE` задает точное имя IANA, например `Europe/Warsaw`
или `UTC`; тогда используется поставляемая база `tzdata==2026.5` / IANA `2026e`.
Та же настройка применяется к XML-датам с явным часовым смещением. Пустое,
неизвестное или небезопасное имя вызывает ошибку без скрытого возврата к ОС.
Данные системного `TZPATH` не подменяют закрепленную базу; сама настройка
ОС не меняется. Результаты рассчитываются для преобразуемого момента,
включая сезонные переходы, а не по текущему смещению. Отдельного сервера 1С, часового пояса сеанса
или информационной базы в автономном интерпретаторе нет; `ТекущаяДатаСеанса`
не добавлена. UTC-функции не используют локальный часовой пояс.

Точность выборки — явная политика этого подмножества: функции, возвращающие
`Дата`, отбрасывают долю секунды; числовая функция отбрасывает долю миллисекунды.
Официальная справка задает смысл функций и начальную точку UTC, но не доказывает
совпадение такой выборки с дробной точностью часов реальной 1С. Сам тип `Дата`
по-прежнему сохраняет шаг 0,1 мс в ранее поддержанной арифметике.

Преобразования выполняются без промежуточного `float` и без округления контекстом
Decimal. Часы вне диапазона календарных лет `1..9999` и ошибки локального
преобразования отклоняются; глобальные настройки часов/часового пояса не меняются.
Результаты используют прежние внутренние кодеки `Дата` и `Число`, в том числе
внутри коллекций. Динамический вывод часов не является нативным эталоном.

### Явные фиксированные смещения GMT

- `МестноеВремя / ToLocalTime(ДатаUTC, ЧасовойПояс)` прибавляет смещение GMT.
- `УниверсальноеВремя / ToUniversalTime(МестнаяДата, ЧасовойПояс)` вычитает его.

Это ограниченное подмножество двух функций: дробные тики даты сохраняются точно,
поддержаны только явно переданные строки `GMT{+/-}h[h][:mm]`. Часы содержат одну или две
ASCII-цифры `0..23`, минуты при наличии — ровно две цифры `00..59`.
Примеры: `GMT+0`, `GMT-00:00`, `GMT+5:30`, `GMT-23:59`. Знак обязателен;
регистр `GMT`, пробелы и форма строки не нормализуются. Нулевые смещения обоих
знаков сохраняют дату. Переносы дня, месяца и года выполняются точно, без `float`
и без зависимости от контекста Decimal, `TZ` или `YADINASSI_TIMEZONE`.

В платформенной сигнатуре второй параметр необязателен, однако здесь пропуск,
`Неопределено` и именованный/компьютерный часовой пояс дают перехватываемую
ошибку неподдержанной операции. Доли секунды не отбрасываются. Даты с неизвестным граничным состоянием также отклоняются. Результат
вне `0001-01-01 00:00:00` — `9999-12-31 23:59:59` отклоняется локальным
ограничением; поведение переполнения реальной 1С для этих функций не заявлено.
Результат имеет существующий тип `Дата` с прежним прямым и обратным внутренним
кодеком, в том числе в коллекциях. Внутренняя запись даты по-прежнему теряет
дробные тики; точность преобразования проверяется числовым вычитанием дат.

Основание — официальные сигнатуры и грамматика фиксированного смещения в справке
EDT (`ToLocalTime4024.html`, `ToUniversalTime4025.html`), а сохранение дробных
тиков подтверждено сервером и управляемым клиентом 1С 8.3.27.1508 в
[прогоне 39758795625](https://github.com/Atridis/yadinassi/actions/runs/39758795625):
0.0001, 0.4999, 0.5 и 0.9999 секунды, обе функции, нулевое/положительное/отрицательное
смещение, переходы дня и обратные композиции. Полная грамматика смещений
проверена локальными инвариантами, а не исчерпывающими нативными измерениями.
Именованные пояса, переходы летнего времени и преобразование часового пояса
компьютера остаются за пределами этого подмножества.

### Календарные функции Date

- `ДобавитьМесяц / AddMonth(Дата, ЧислоМесяцев)` принимает дату и конечное число.
  Число месяцев усекается к нулю; день ограничивается последним днем целевого
  месяца. Часы, минуты и целые секунды сохраняются, доля секунды отбрасывается
  даже при нулевом сдвиге. Последовательные сдвиги могут отличаться от одного
  суммарного сдвига из-за ограничения дня.
- `НачалоМинуты / BegOfMinute`, `КонецМинуты / EndOfMinute`,
  `НачалоЧаса / BegOfHour`, `КонецЧаса / EndOfHour`,
  `НачалоДня / BegOfDay`, `КонецДня / EndOfDay`,
  `НачалоНедели / BegOfWeek`, `КонецНедели / EndOfWeek`,
  `НачалоМесяца / BegOfMonth`, `КонецМесяца / EndOfMonth`,
  `НачалоКвартала / BegOfQuarter`, `КонецКвартала / EndOfQuarter`,
  `НачалоГода / BegOfYear`, `КонецГода / EndOfYear` принимают одну дату.
  Результаты имеют целые секунды: конец периода — последняя целая секунда,
  не последний тик. Неделя начинается в понедельник.
- `ДеньГода / DayOfYear(Дата)` возвращает порядковый день 1–365/366;
  `ДеньНедели / WeekDay(Дата)` — понедельник 1 … воскресенье 7;
  `НеделяГода / WeekOfYear(Дата)` — номер недели, где 1 января всегда относится
  к неделе 1, а следующий понедельник начинает новую неделю. Это не ISO-нумерация:
  04.01.2016 — неделя 2. Доли секунды на нумерацию не влияют.
- Обычные результаты поддержаны в григорианском диапазоне 0001–9999;
  календарные функции не принимают строки/числа вместо даты и не работают
  с прежними непроверенными граничными состояниями арифметики.
- Только для точных проб `AddMonth(Date(1,1,1),-1)` и
  `AddMonth(Date(9999,12,31,23,59,59),1)` известна скалярная запись минимальной
  даты, а для `EndOfWeek(Date(9999,12,31,23,59,59))` — максимальной.
  У этих результатов разрешены только скалярный внутренний кодек и `ТипЗнч`;
  скрытое состояние тиков не считается установленным. Остальные выходы месяца
  или конца недели за диапазон, включая дробные счетчики/исходные даты у границ,
  отклоняются, даже если усечение счетчика дало бы проверенное целое число.
- Защитный предел счетчика месяцев — 4096 цифр коэффициента; величины за
  ±120000 отклоняются до преобразования в целое, поскольку результат такого
  сдвига не может попасть в поддержанный диапазон. Это предел реализации,
  а не утверждение о поведении 1С вне проверенной области.

### Работа с текстом

Здесь перечислен API функций, без описания примитивного типа и его синтаксиса.

- `СтрДлина / StrLen(Текст)`.
- `Символ / Char(Код)`, `КодСимвола / CharCode(Текст [, Позиция = 1])`.
- `Лев / Left(Текст, Количество)`, `Прав / Right(Текст, Количество)`,
  `Сред / Mid(Текст, Начало [, Количество])`.
- `Найти / Find(Текст, Подстрока)` — прямой поиск первого вхождения.
- `СтрНайти / StrFind(Текст, Подстрока [, Направление, Начало, НомерВхождения])`.
  Поиск чувствителен к регистру, без нормализации Unicode; результат — позиция
  первого символа совпадения от 1 или 0, если нужного вхождения нет.
  Направление по умолчанию — `НаправлениеПоиска.СНачала`; обратное направление —
  `НаправлениеПоиска.СКонца`. Начало по умолчанию — 1 или длина строки
  соответственно; для пустого текста — 1. У обратного поиска начало ограничивает
  позицию первого символа совпадения, а не последнего. Номер вхождения по умолчанию —
  1; непустые совпадения считаются без пересечений от выбранной начальной позиции.
  Дробные позиции и номера усекаются к нулю; числовые строки принимаются.
  Явная позиция должна попадать в `1..Макс(1, СтрДлина(Текст))` после усечения.
  Нулевой номер отклоняется, отрицательный возвращает 0.
  Явное `Неопределено` вместо начала использует умолчание;
  вместо направления или номера вхождения оно отклоняется. Пустые необязательные
  позиции между запятыми используют умолчания; первые два аргумента обязательны.
  Для пустой подстроки после проверки аргументов номер 1 дает 1, положительный
  номер больше 1 — нормализованное начало. Нативно проверены отдельные случаи
  с номерами 1, 2, 3; обобщение на остальные комбинации — правило реализации,
  а не исчерпывающая проверка 1С. Подробности и примеры — в `features.md`.
  `Найти / Find` дополнительных параметров не имеет.
- `СтрЗаменить / StrReplace(Текст, Подстрока, Замена)`.
- `СтрНачинаетсяС / StrStartsWith(Текст, Подстрока)`,
  `СтрЗаканчиваетсяНа / StrEndsWith(Текст, Подстрока)`.
- `СокрЛ / TrimL(Текст)`, `СокрП / TrimR(Текст)`, `СокрЛП / TrimAll(Текст)`,
  `ПустаяСтрока / IsBlankString(Текст)`.
- `ВРег / Upper(Текст)`, `НРег / Lower(Текст)`.
- `СтрРазделить / StrSplit(Текст, Разделители [, ВключатьПустые = Истина])` — массив;
  разделители трактуются как набор символов.
- `СтрСоединить / StrConcat(Массив [, Разделитель = ""])` — принимает также
  фиксированный массив.
- `СтрЧислоВхождений / StrOccurrenceCount(Текст, Подстрока)`.
- `СтрЧислоСтрок / StrLineCount(Текст)`, `СтрПолучитьСтроку / StrGetLine(Текст, Номер)`.
- `СтрШаблон / StrTemplate(Шаблон [, Значения...])` — до десяти значений,
  маркеры `%1`–`%10`, `%(1)`–`%(10)` и `%%`.
- `СтрСравнить / StrCompare(ПервыйТекст, ВторойТекст)` — сравнение без учета регистра,
  результат `-1`, `0` или `1`; аргументы должны быть текстовыми.

Позиции и длины текстовых функций считаются в кодовых единицах UTF-16, позиции
начинаются с единицы. Реализованное сравнение и преобразование регистра не означает
поддержку всех локалей платформы; границы совместимости описаны в `features.md`.

### Числовые и побитовые функции

- `Цел / Int(Значение)`.
- `Sqrt(Число)`, `Log(Число)`, `Log10(Число)`, `Exp(Число)`,
  `Sin(Угол)`, `Cos(Угол)`, `Tan(Угол)`, `ASin(Число)`, `ACos(Число)`,
  `ATan(Число)`, `Pow(Основание, Показатель)`. Эти имена совпадают в русской
  и английской документации; регистр не важен. Углы — в радианах.
  Числовое приведение совпадает с `Число / Number`, включая строки и булевы.
  Области определения проверяются до двоичного преобразования: корень требует
  неотрицательного аргумента, логарифмы — положительного, `ASin`/`ACos` — [-1, 1].
  Отрицательное основание `Pow` требует точно целого показателя; ноль в
  отрицательной степени отклоняется. `Pow(0, 0)` возвращает 1.
  Целая неотрицательная степень сохраняет десятичный коэффициент точно,
  отрицательная использует действующую модель деления с ее ограничениями.
  Остальные операции используют эмпирическое преобразование десятичных блоков
  по девять цифр и результат с 15 значащими цифрами. `Exp` вычисляется в отдельном
  Decimal-контексте с 80, 160 или 320 цифрами: соседние десятичные значения
  ограничивают точный результат; их одинаковое преобразование в binary64
  подтверждает округление, включая субнормальные значения и переполнение.
  Если границы не дают одинаковый binary64 за 320 цифр, возникает явная ошибка
  неподдержанного округления. Другие функции используют библиотеку binary64.
  Это обобщение нативных наблюдений, а не доказательство одинакового округления
  любого аргумента на всех реализациях математической библиотеки.
  Локальный диапазон двоичного преобразования: нормализованный коэффициент,
  выровненный к блокам по девять цифр, не длиннее 306 цифр; модуль показателя
  масштаба не больше 34 блоков (306 десятичных позиций). Неконечное двоичное
  преобразование отклоняется. Для крайних диапазонов нет запасного алгоритма
  с неподтвержденным округлением. Это предел модели Yadinassi, не предел 1С.
  Если блочное округление допустимого аргумента `ASin`/`ACos` выходит за [-1, 1]
  (например, дробь из 37 девяток после запятой), возвращается явная ошибка
  неподтвержденной границы модели. Автоматического прижатия к ±1 нет.
  Для целого `Pow` коэффициент и модуль десятичного масштаба ограничены 4096
  разрядами; положительный масштаб вместе с коэффициентом также укладывается
  в 4096 цифр. Промежуточная положительная степень для отрицательного
  показателя должна пройти эти же проверки. Деление дополнительно ограничивает
  свои промежуточные величины и пока отклоняет точную половину на границе
  округления (например, `Pow(2, -28)`). Ноль и основания ±1 обрабатываются
  без развертывания огромного целого показателя. Внутренний кодек сохраняет
  собственный предел длины представления числа.
- `ЧислоИзДвоичнойСтроки / NumberFromBinaryString(Текст)`,
  `ЧислоИзШестнадцатеричнойСтроки / NumberFromHexString(Текст)` — точное число
  из ASCII-цифр со строго строчными префиксами `0b` / `0x`. Ноль и начальные
  нули разрешены; шестнадцатеричные цифры нечувствительны к регистру.
  Пробелы, знаки, дроби и посторонние символы не допускаются; аргумент текстовый.
  Нативно подтверждены значения до максимума 128 бит (39 десятичных цифр).
  Локальный предел: 4096 двоичных или 1024 шестнадцатеричных цифр, включая
  начальные нули; он не является заявлением о нативной максимальной разрядности.
- `Мин / Min(ПервоеЗначение [, Значения...])`,
  `Макс / Max(ПервоеЗначение [, Значения...])` — минимум один аргумент;
  либо текстовые аргументы, либо числовые/булевы. Возвращают исходный выбранный
  аргумент, при равенстве — первый.
- `Окр / Round(Значение [, Разрядность = 0, Режим = РежимОкругления.Окр15как20])` —
  принимает значения системного перечисления или числовой режим.
- `ПобитовоеИ / BitwiseAnd(Первое, Второе)`,
  `ПобитовоеИли / BitwiseOr(Первое, Второе)`,
  `ПобитовоеИсключительноеИли / BitwiseXor(Первое, Второе)`,
  `ПобитовоеИНе / BitwiseAndNot(Первое, Второе)`,
  `ПобитовоеНе / BitwiseNot(Значение)`.
- `ПроверитьБит / CheckBit(Значение, Позиция)`,
  `ПроверитьПоБитовойМаске / CheckByBitMask(Значение, Маска)`,
  `УстановитьБит / SetBit(Значение, Позиция, Установлен)`.
- `ПобитовыйСдвигВправо / BitwiseShiftRight(Значение, Смещение)` — беззнаковый
  сдвиг с заполнением нулями.
- `ПобитовыйСдвигВлево / BitwiseShiftLeft(Значение, Смещение)` — сдвиг
  с отбрасыванием старших битов за границей 32 бит.

Побитовые операции принимают целые числа `0..4294967295`, позиции и смещение —
`0..31`; `Установлен` должен быть булевым. Неявные преобразования других типов
не поддержаны. Переполнение сдвига влево подтверждено нативными пробами PR52.

### Преобразования XML

- `XMLСтрока / XMLString(Значение)`.
- `XMLЗначение / XMLValue(ТипЗначения, Текст)`.

Поддержаны `Строка`, `Булево`, `Число`, `Null` и `Неопределено`;
для `Дата` поддержаны обе функции. XML-запись даты отбрасывает дробные тики.
XML-чтение принимает точные ASCII-формы `YYYY-MM-DD` или
`YYYY-MM-DDTHH:MM:SS[.цифры][Z|±HH:MM]`. Доля секунды округляется до ближайшей
целой секунды, половина вверх, с переносом суток; вычисление не зависит от
Decimal-контекста. Зона применяется после округления: явное смещение переводится
в UTC, затем в локальный календарь процесса/`YADINASSI_TIMEZONE` на этот момент.
Без зоны значение остается календарным и не зависит от конфигурации.
Границы: годы 0001–9999, секунды 00–59, смещения до ±14:00, максимум 4096
символов входа. Непроверенные выходы за диапазон отклоняются без насыщения.
Это ограниченная поддержанная грамматика, не перечень всех форм, принимаемых 1С.
Числа записываются точно, без экспоненты, незначащих конечных нулей и `-0`.
Чтение принимает ограниченную ASCII-десятичную форму с XML-пробелами;
экспонентный или десятично-запятой суффикс отбрасывается, как в нативных
`1e3`, `1E-3` и `1,5`. Произвольные суффиксы и Unicode-пробелы не заявлены.
Для `Null`/`Неопределено` поддержана только пустая XML-строка.
Лимит числовой записи — 4096 разрядов, защитное ограничение Yadinassi.
Это лексические преобразования, не XML-парсер: сущности и экранирование
не обрабатываются.

`ОбработкаСтрокиXML / XMLStringProcessing` предоставляет метод
`УдалитьНедопустимыеСимволыXML / DeleteDisallowedXMLCharacters(Текст, ВерсияXML = "1.0")`.
Версии `"1.0"` и `"1.1"` удаляют недопустимые символы буквального текста;
1.1 дополнительно удаляет ограниченные управляющие символы. Корректная пара
UTF-16 сохраняется, отдельные суррогаты удаляются без повторного соединения.
Разметка и записи сущностей остаются буквальным текстом. Лимит работы —
1 048 576 кодовых единиц UTF-16, не заявленный предел платформы.
Менеджер имеет собственный `Тип` и настоящий внутренний кодек; обратное
чтение записи менеджера дает `Неопределено`, а запись его типа восстанавливает тип.
Другие методы менеджера пока не предоставляются.

Нативный XML-префикс `values.out` подтверждает все 62 наблюдения; его 784 строки
сохраняются внутри полного сравнения текущего файла. Часовой пояс запуска подтвержден владельцем и записан в
[docs/native-testing.md](docs/native-testing.md#xml-checkpoint-timezone-2026-10-19); воспроизведение использует явный `Europe/Warsaw`.
Это CLDR-сопоставление, не обещание полного исторического тождества Windows/IANA.
Подробности и границы доказанного поведения — в `features.md`.

### Внутреннее представление значений

- `ЗначениеВСтрокуВнутр / ValueToStringInternal(Значение)`.
- `ЗначениеИзСтрокиВнутр / ValueFromStringInternal(Представление)`.

Поддержаны примитивные значения, включая `Дата / Date` и `Null`, шесть базовых коллекций выше, шесть типов семейства `ТаблицаЗначений`, `СписокЗначений`,
`ЭлементСпискаЗначений`, `КлючИЗначение`, `Тип`,
значения и пространства `РежимОкругления`, `НаправлениеПоиска`, `ДопустимыйЗнак`,
`ДопустимаяДлина`, `ЧастиДаты`, скалярное `ОписаниеТипов` и квалификаторы.
Также поддержаны значения `НаправлениеСортировки` и запись их типа,
но не само пространство этого перечисления.
Значения перечислений восстанавливаются как те же значения; записи самих
пространств при обратном чтении дают `Неопределено` согласно нативным пробам.
Их отдельные записи `Тип` сохраняют идентичность соответствующего типа,
включая тип пространства, недоступный через `Тип(Имя)`.
Поддержка ограничена реализованными формами внутреннего потока 1С: это не JSON
и не обещание совместимости с произвольным внутренним представлением платформы.
Циклы и неизвестные теги отклоняются; общая идентичность повторяющихся вложенных
объектов не сохраняется как граф ссылок.

Таблица записывается как канонический снимок версии 9 с текущими последовательными
идентификаторами строк/колонок и текущими определениями индексов, без исторических ID. Обратное чтение
создает независимую таблицу; отдельные записи строки, колонки, коллекции колонок,
индекса и коллекции индексов
читаются как `Неопределено`. Их записи `Тип` сохраняют тип. Дополнительно к общим
лимитам кодека таблица ограничена 10 000 ячейками; типы и квалификаторы ячеек
проверяются без исправления входного потока.

Список значений восстанавливается как независимый список с сохранением порядка,
ID и истории их выделения. Поддержана только наблюдаемая форма с описанием типов,
пустой картинкой и флагами по умолчанию. Отдельный элемент восстанавливается
как новый `ЭлементСпискаЗначений` с сохранением внутреннего ID, но вызов `GetID`
для него не заявлен. Записи типов списка и элемента сохраняют тип. Неизвестные
версии, флаги, картинки и нестандартные ограничения отклоняются.

`Null` записывается как `{"L"}` и восстанавливается как то же специальное
значение. Его `Тип` и вложенные записи поддерживают прямое и обратное чтение;
этот формат подтвержден настоящим нативным `values.out`.

Внутренний кодек даты сохраняет только целые секунды: обратное чтение
теряет дробь, наблюденную в арифметике. Чтение `D` ограничено точной
14-цифровой канонической записью; идентичность `Тип("Дата")` сохраняется.

Лимиты кодека Yadinassi: 1 048 576 символов представления, глубина 64,
10 000 узлов и 4 096 десятичных разрядов для числового представления.
Это защитные ограничения реализации, а не заявленные пределы платформы 1С.

## Описание скалярных типов

`ОписаниеТипов / TypeDescription` принимает строку имен или массив значений
`Тип` для Булево/Строка/Дата/Число и отдельного Null; поддержаны пустое описание,
удаление повторов, независимый `Типы / Types()`, `СодержитТип / ContainsType`,
копирование с добавлением/удалением и переопределением квалификаторов.
`ПривестиЗначение / AdjustValue` реализует наблюденные скалярные преобразования,
умолчания, округление/насыщение числа, UTF-16 усечение/дополнение строки и части
даты; точные границы приведены в `features.md`. Все свойства только для чтения.
Внутренний `Pattern` сохраняет поддержанные типы и квалификаторы при обратном
чтении, в том числе в значениях коллекций. Статический `Новый` нельзя соединять
с доступом к члену даже через скобки: используйте промежуточную переменную.

## Квалификаторы и перечисления ограничений

- `КвалификаторыЧисла / NumberQualifiers`, `КвалификаторыСтроки / StringQualifiers`,
  `КвалификаторыДаты / DateQualifiers`, `КвалификаторыДвоичныхДанных / BinaryDataQualifiers`:
  конструкторы, русские/английские свойства только для чтения, `Тип`/`ТипЗнч`.
- `ДопустимыйЗнак / AllowedSign`: `Любой / Any`, `Неотрицательный / Nonnegative`;
  `ДопустимаяДлина / AllowedLength`: `Фиксированная / Fixed`, `Переменная / Variable`;
  `ЧастиДаты / DateFractions`: `Дата / Date`, `Время / Time`, `ДатаВремя / DateTime`.
  Значения непрозрачны и не являются числами. Пространства доступны глобально,
  их тип получается через `ТипЗнч`, без обещания разрешения имени пространства через `Тип`.
- Числовые разрядности и длины принимают конечные числа и числовые строки;
  положительная дробная часть отбрасывается, отрицательное целое количество
  нормализуется в ноль. Дробная разрядность ограничивается общей. Длина ноль
  нормализует `Fixed` в `Variable`; 39 числовых разрядов допустимы.
- Значения перечислений и записи всех новых типов имеют настоящий внутренний
  кодек с обратным чтением. Отдельные квалификаторы и пространства перечислений
  записываются без параметров: их нативное обратное чтение дает `Неопределено`,
  в том числе внутри коллекций. Такая запись не сохраняет настройки квалификатора.
- Защитные пределы Yadinassi: 4 096 числовых разрядов и 1 000 000 единиц длины.
  Это бюджеты реализации, а не ограничения настоящей 1С.

## ДеревоЗначений / ValueTree — ограниченные нативные наблюдения

Поддерживаются конструктор без параметров, общие `Колонки/Columns`, корневые и
дочерние `Строки/Rows`; операции строк `Добавить/Add`, `Вставить/Insert`,
`Удалить/Delete`, `Очистить/Clear`, `Количество/Count`, `Получить/Get`,
`Индекс/IndexOf`. Обход коллекции строк ограничен непосредственными детьми;
обход строки возвращает ячейки. Ячейки доступны по имени и индексу, через
`Получить/Get`, `Установить/Set` и по ссылке. `Родитель/Parent` только для чтения;
`Владелец/Owner` возвращает дерево, `Уровень/Level` начинается с 0 (наблюдалось
в ограниченном прогоне 40221284540). Пять представлений TypeOf исправлены по
нативным байтам; RU/EN Type/TypeOf идентичности и конструкторные имена сохранены.
Полная приемка после исправления еще ожидается; представления самих объектов
этими наблюдениями не подтверждены.
Точные ограничения и статус доказательств: [docs/value-tree-core.md](docs/value-tree-core.md).
