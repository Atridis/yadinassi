# Возможности языка

Описание новых возможностей интерпретатора и примеры их использования.

## Условное выражение

Поддерживается конструкция `?(Условие, ВыражениеЕслиИстина, ВыражениеЕслиЛожь)`:

```bsl
Делитель = 0;
Результат = ?(Делитель = 0, 0, 100 / Делитель);
Сообщить(Результат); // 0, деление на ноль не выполняется
```

Условие вычисляется один раз, затем вычисляется только выбранное выражение.
Тип и значение результата сохраняются; допускаются вложенные условные выражения.
Синтаксис обеих ветвей проверяется до исполнения программы. Условие использует
то же преобразование в булево значение, что и `Если`.

Поведение выбора ветви соответствует
[описанию 1С:Предприятия 8.3, раздел 4.6.5.2](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_8.3.23_Developer_Guide/Chapter_4._1C_Enterprise_language/4.6._Statements_and_syntax_structures/4.6.5._Conditional_statements/?language=en).
Это отдельный шаг расширения поддерживаемого подмножества языка, а не заявление
о полной совместимости с платформой 1С.

## Функции и процедуры без параметров

В модуле можно объявлять и вызывать собственные функции и процедуры:

```bsl
Перем Счетчик;

Процедура Показать() Экспорт
    Сообщить(СледующееЗначение());
КонецПроцедуры

Функция СледующееЗначение()
    Счетчик = Счетчик + 1;
    Возврат Счетчик;
КонецФункции

Счетчик = 0;
Показать(); // 1
Показать(); // 2
```

- Поддерживаются русские и английские ключевые слова, регистр не важен.
- Объявления регистрируются до исполнения кода модуля; тело выполняется только
  при вызове. Функция может вызывать другую функцию, объявленную ниже, и себя.
- `Возврат Выражение;` возвращает значение функции. `Возврат;` завершает вызов,
  в том числе из вложенных циклов. Функция без возвращенного значения дает
  `Неопределено`. Процедуру нельзя использовать как значение выражения.
- Каждый вызов получает свои локальные переменные. Общие переменные нужно явно
  объявить через `Перем` на уровне модуля; локальное `Перем` скрывает одноименную
  переменную модуля. Переменные, созданные присваиванием в основном коде без
  `Перем`, из функций и процедур недоступны.
- В интерактивной консоли объявления сохраняются между командами; повторное
  объявление в следующей команде заменяет предыдущее. Дубликаты в одной программе
  запрещены. Незавершенное объявление можно продолжить на следующих строках.

`Экспорт` открывает подпрограмму для вызова из импортирующего модуля
(импорт отдельных файлов описан ниже). Поддерживается клиентская директива
исполнения, описанная в разделе ниже; вложенные объявления пока не поддерживаются.
Поддержка параметров описана ниже. Функцию можно вызвать как отдельный оператор, отбросив результат.
После `КонецФункции` и `КонецПроцедуры` точка с запятой не требуется.

Ориентир для семантики: [руководство 1С, процедуры](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_8.3.23_Developer_Guide/Chapter_4._1C_Enterprise_language/4.6._Statements_and_syntax_structures/4.6.3._Procedure/)
и [руководство разработчика 8.3.27, разделы 4.5–4.6](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/).


## Позиционные параметры функций и процедур

```bsl
Функция ПолучитьСумму(Знач Первое, Знач Второе)
    Возврат Первое + Второе;
КонецФункции

Процедура Увеличить(Число)
    Число = Число + 1;
КонецПроцедуры

Сообщить(ПолучитьСумму(1, 2)); // 3
Счетчик = 10;
Увеличить(Счетчик);
Сообщить(Счетчик); // 11
```

- Параметры перечисляются через запятую; аргументы сопоставляются по позиции.
  Имена не зависят от регистра. Дублирующиеся параметры и повторное объявление
  параметра через `Перем` запрещены.
- По умолчанию переданная переменная связывается с параметром по ссылке:
  присваивание параметру сразу меняет переменную вызывающего кода. Связь
  сохраняется при передаче параметра другой подпрограмме. Если одну переменную
  передать дважды, оба параметра видят изменения друг друга.
- `Знач` / `Val` создает локальное значение параметра: присваивание ему не
  меняет переменную вызывающего кода. Это не глубокое копирование: методы
  переданного массива по-прежнему изменяют тот же массив.
- Литералы, результаты вызовов и вычисляемые выражения передаются через временное
  значение. Например, изменение параметра при вызове `Увеличить(Счетчик + 0)`
  не изменяет `Счетчик`. Группировка вычисляемых выражений поддерживается:
  `Увеличить((Счетчик + 0))` и `Увеличить((Счетчик) + 0)`.
- Аргументы вычисляются один раз слева направо в контексте вызывающего кода.
  Параметры локальны для каждого вызова и скрывают одноименные переменные модуля.
  Рекурсивные вызовы получают отдельные наборы параметров.
- Число аргументов проверяется до вычисления аргументов и исполнения тела.
  Значения по умолчанию и пропущенные позиции описаны ниже.
- Для параметра без `Знач` пока запрещены аргументы вида `Массив[0]`, `Объект.Свойство`
  и переменная, целиком заключенная в скобки, например `(Счетчик)`. Для этих
  граничных случаев совместимость с 1С еще не проверена, поэтому интерпретатор
  не подменяет их молча передачей по значению. Используйте `Знач` или отдельную
  переменную, учитывая, что отдельная переменная не изменит исходное свойство
  или элемент массива автоматически. Параметры `Знач` принимают обычные
  выражения, в том числе `Массив[0]` и `(Счетчик)`.
- Выходную переменную можно предварительно объявить через `Перем` (ее начальное
  значение — `Неопределено`). Сам вызов не объявляет неизвестные переменные.

Семантика ссылки и `Знач` основана на
[официальном описании передачи параметров 1С](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Standards/1C_Enterprise_script/).
Правила объявления переменных и параметров описаны в
[руководстве 8.3.27, разделы 4.3.1, 4.6.1 и 4.7.4](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/?sphrase_id=1678862).
Это ограниченное подмножество, а не полная совместимость параметров с 1С.
Тесты интерпретатора не заменяют сравнительные прогоны на платформе 1С.


## Значения параметров по умолчанию и пропущенные аргументы

```bsl
Функция Описание(Знач Имя = "Гость", Знач Количество = 1)
    Возврат Имя + ": " + Строка(Количество);
КонецФункции

Сообщить(Описание()); // Гость: 1
Сообщить(Описание("Анна")); // Анна: 1
Сообщить(Описание(, 3)); // Гость: 3
```

- В объявлении поддерживаются литералы чисел (включая знак `+` или `-`), строк,
  булевых значений и `Неопределено` / `Undefined`. Выражения, имена переменных,
  вызовы и создание объектов как значения по умолчанию запрещены. Даты и `Null`
  пока не входят в поддерживаемое подмножество значений интерпретатора.
- Параметры со значением по умолчанию могут стоять в любой позиции, в том числе
  перед обязательными. Полностью опустить в конце вызова можно только параметры
  со значениями по умолчанию.
- Внутри списка можно явно пропускать позиции: `П(, 2)` или `П(1, , 3)`.
  Такая позиция получает значение по умолчанию, а при его отсутствии —
  `Неопределено`. Конечные необязательные параметры опускаются без запятой.
- Вызовы с запятой непосредственно перед `)` (например, `П(1,)`, `П(,,)`)
  пока дают явную диагностику. Описание пропуска в руководстве и пустые узлы
  грамматики EDT не позволяют без прогона на платформе уверенно установить
  поведение всех конечных пустых позиций; интерпретатор не выбирает его молча.

```bsl
Процедура Показать(Первый, Второй = "по умолчанию", Третий = 16)
    Сообщить(Первый = Неопределено);
    Сообщить(Второй);
    Сообщить(Третий);
КонецПроцедуры

Показать(, "пример"); // Да; пример; 16
// Показать(); // ошибка: обязательный Первый полностью опущен
```

- Явно переданное `Неопределено` остается значением аргумента и не заменяется
  объявленным значением по умолчанию.
- Параметр, полученный из значения по умолчанию или пропущенной позиции, локален
  для вызова; его изменение не влияет на следующие вызовы. Обычные явно
  переданные переменные сохраняют поведение ссылки, а `Знач` — передачи значения.
- Лишние аргументы и полностью опущенные обязательные параметры диагностируются
  до вычисления аргументов и выполнения тела.
- Явный пропуск позиций встроенных функций, методов и конструкторов пока
  диагностируется как неподдерживаемый. Например, `Новый Массив()` работает,
  а `Новый Массив(, 1)` не подменяется Python-значением `None`.

Правила пропущенных позиций и объявления значений по умолчанию основаны на
[руководстве 1С:Предприятия 8.3.27, разделах 4.6.3 и 4.7.4.4](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/).
Ограничение значений по умолчанию литералами и отдельным знаком числа соответствует
[грамматике параметров 1C:EDT](https://edt.1c.ru/dev/edt/2024.2/apidocs/com/_1c/g5/v8/dt/bsl/parseTreeConstruction/BslParsetreeConstructor.FormalParam_Group.html).
Неоднозначные конечные пустые позиции остаются неподдерживаемыми с учетом
[грамматики вызова 1C:EDT](https://edt.1c.ru/dev/edt/2024.2/apidocs/com/_1c/g5/v8/dt/bsl/parseTreeConstruction/BslParsetreeConstructor.FeatureResolving_Group.html).
Сравнительный прогон на платформе 1С в рамках этого изменения не выполнялся.


## Импорт отдельного файла

`// #Импорт` — расширение yadinassi для подключения собственных файлов.
Для платформы 1С эта строка остается обычным комментарием и не создает
неизвестной директивы препроцессора; само подключение файлов выполняет только
Yadinassi. Наличие комментария не делает последующий вызов внешнего модуля
автоматически исполняемым на 1С. Оба файла в примере лежат в одном каталоге.

Прежний синтаксис `# Импорт` больше не поддерживается. Для миграции добавьте
`// ` перед каждой такой строкой, например `// #Импорт Побочное.bsl`.

Файл `Побочное.bsl`:

```bsl
Функция ПолучитьСумму(Число1, Число2) Экспорт
    Возврат Число1 + Число2;
КонецФункции
```

Файл `Основное.bsl`:

```bsl
// #Импорт Побочное.bsl

Сообщить(Побочное.ПолучитьСумму(1, 2)); // 3
```

Запуск: `yadinassi Основное.bsl`.

- Комментарий-директива занимает отдельную строку на уровне модуля, без точки
  с запятой. Перед `//` допустимы пробелы; пробелы после `//` и `#` необязательны.
  Поддерживаются `Импорт` / `Import` без учета регистра. В конце строки допустим
  дополнительный комментарий `//`. Текст в строковом литерале, обычном комментарии
  или комментарии после оператора импортом не становится. Имя файла должно
  состоять из идентификатора и `.bsl`;
  перед ним можно указать каталоги через точки, как показано ниже.
- Путь разрешается относительно файла, содержащего директиву, а не текущего
  рабочего каталога. Написание имени файла должно совпадать с именем на диске
  с учетом правил файловой системы. Имя пространства модуля (имя без `.bsl`)
  и имена вызываемых подпрограмм не зависят от регистра.
- При подключении сначала выполняется основной код импортируемого модуля.
  Все импорты загружаются до операторов импортирующего модуля, в порядке
  директив. Подпрограммы регистрируются до инициализации, как и в обычном файле.
- Каждый файл имеет отдельные переменные и подпрограммы. Через имя модуля можно
  вызвать только функцию или процедуру с `Экспорт`; собственные закрытые
  подпрограммы доступны внутри этого файла. Переменные модуля снаружи недоступны.
- Передача по ссылке, `Знач`, значения по умолчанию, пропуск внутренних позиций
  и проверка количества аргументов работают так же, как при обычном вызове.
  Процедуру нельзя использовать как значение выражения.
- Успешно загруженный файл и его состояние сохраняются в кэше одного
  интерпретатора. Повторные и транзитивные импорты используют тот же экземпляр;
  основной код повторно не выполняется. Другой интерпретатор имеет свой кэш.
  Неудачная загрузка самого модуля в кэш не попадает; уже успешно загруженные
  зависимости сохраняются. Циклический импорт дает ошибку с цепочкой файлов.
- Имя импорта на уровне модуля нельзя переобъявлять или менять присваиванием.
  Параметры и локальные переменные могут скрывать его внутри подпрограммы.
  Пространство модуля не является значением: передавать его как аргумент,
  сохранять в переменную или извлекать функцию без вызова пока нельзя.
- Файлы читаются как UTF-8 с необязательным BOM. Параметр CLI `--encoding`
  применяется и к импортам. Ошибки чтения указывают место директивы и путь,
  ошибки синтаксиса и исполнения внутри модуля — его исходный файл и строку.

### Явный импорт файла из вложенного каталога

Если файл `Побочное.bsl` из примера находится в каталоге `Справочник` рядом
с `Основное.bsl`, директива и вызов выглядят так:

```bsl
// #Импорт Справочник.Побочное.bsl

Сообщить(Справочник.Побочное.ПолучитьСумму(1, 2)); // 3
```

- Точки перед расширением обозначают каталоги: `Справочник.Побочное.bsl`
  загружает `Справочник/Побочное.bsl` относительно импортирующего файла.
  Допускается несколько уровней, например `Библиотека.Справочник.Побочное.bsl`
  и вызов `Библиотека.Справочник.Побочное.ПолучитьСумму(1, 2)`.
- Каждая директива подключает ровно один явно названный файл. Несколько импортов
  с общим началом объединяют пространство имен: `Справочник.Побочное.bsl` и
  `Справочник.Другое.bsl` доступны одновременно. Коллизия модуля и каталога,
  например `Справочник.bsl` и `Справочник.Побочное.bsl`, дает ошибку.
- В директивах используйте точное написание каталогов и файлов на диске:
  регистр путей не нормализуется. Это обеспечивает одинаковую работу на разных
  файловых системах; варианты одного пути, отличающиеся только регистром,
  не гарантированно объединяются. Все части имени в вызове, включая каталоги,
  имя модуля и подпрограммы, не зависят от регистра.
- Вложенные модули сохраняют описанные выше правила экспорта, инициализации,
  кэширования, параметров и диагностики. Их собственные импорты разрешаются
  относительно их файлов.

### Импорт каталога

Чтобы подключить все файлы `.bsl` непосредственно из каталога `Справочник`:

```bsl
// #Импорт Справочник

Сообщить(Справочник.Побочное.ПолучитьСумму(1, 2)); // 3
```

- Имя без завершающего `.bsl` обозначает каталог. Допускаются точки между
  уровнями: `// #Импорт Библиотека.Справочник`. Путь отсчитывается от
  импортирующего файла; все части должны быть идентификаторами, не ключевыми словами.
- Подключаются только непосредственные файлы с расширением `.bsl` без учета
  регистра расширения. Подкаталоги (даже с именем `Имя.bsl`) и другие файлы
  игнорируются, как и специальные файлы (например, именованные каналы);
  рекурсивного поиска нет. Пустой каталог создает пустое
  пространство имен. Отсутствующий каталог дает ошибку на директиве.
- Порядок загрузки определяется сортировкой имен файлов без учета регистра,
  затем исходным написанием. Собственные импорты модуля могут загрузить его
  зависимости раньше. Недопустимое имя файла `.bsl` или совпадение имен без
  учета регистра дает ошибку до инициализации любого файла этой директивы.
- Явный импорт файла и импорт его каталога совместимы в любом порядке;
  повторное подключение не сбрасывает состояние уже загруженных модулей.
  Повторная директива снова просматривает каталог и может добавить новые файлы.
  Ранее подключенные модули остаются доступны при удалении файлов с диска.
- Коллизии с существующими модулями и каталогами проверяются до загрузки.
  Все новые имена публикуются только после успешной загрузки всего каталога.
  При ошибке уже выполненные побочные эффекты не отменяются, успешно
  загруженные модули остаются в общем кэше; после исправления ошибочного файла
  директиву можно повторить без повторной инициализации успешных модулей.
- Символические ссылки разрешаются в канонические пути; ссылки на один файл
  используют один кэш. Относительные импорты внутри него разрешаются от
  канонического файла. Циклические импорты дают диагностику.
- Правила экспорта, параметров, кодировки и доступа к пространствам имен
  совпадают с явным импортом файла.

Пути с разделителями `/` или `\`, экспорт переменных и импорт из консоли, `-c` или
стандартного ввода пока не поддерживаются и дают диагностику. Для встраивания
через Python нужно передать `execute` имя исходного файла в `source`.
Клиентский контекст и поддерживаемые директивы исполнения описаны ниже.


## Клиентский контекст и условная компиляция

Корневой скрипт, интерактивная консоль и импортированные модули исполняются
в единственном клиентском контексте Yadinassi. Это самостоятельный режим
интерпретатора: он не эмулирует сервер, тонкий/толстый/веб-клиент или управляемые
формы 1С и не предоставляет весь клиентский API платформы. В Python API
`Interpreter.execution_context` возвращает `"client"` (свойство только для чтения).

Перед объявлением функции или процедуры можно явно указать `&НаКлиенте`
или `&AtClient`. Без директивы подпрограмма также клиентская:

```bsl
&НаКлиенте
Функция Сумма(Знач Первое = 20, Знач Второе = 22) Экспорт
    Возврат Первое + Второе;
КонецФункции

&AtClient
Процедура Показать()
    Сообщить(Сумма());
КонецПроцедуры

Показать(); // 42, корневой код также клиентский
```

- Директива занимает отдельную строку перед подпрограммой уровня модуля;
  разрешены отступ, комментарий `//`, пустые строки перед объявлением.
- Регистр букв не важен. Параметры, значения по умолчанию, `Экспорт`, рекурсия
  и вызовы через импорт сохраняют прежнюю семантику.
- Директивы сервера и совместного клиент-серверного исполнения, включая
  `&НаСервере`, `&НаСервереБезКонтекста`, `&НаКлиентеНаСервере`,
  `&НаКлиентеНаСервереБезКонтекста` и английские варианты, явно отклоняются.
  Неизвестные аннотации, повторные директивы и директивы перед операторами
  также являются ошибками, а не молча игнорируются.

Для выбора клиентского текста до разбора BSL поддерживаются
`#Если Условие Тогда`, `#ИначеЕсли Условие Тогда`, `#Иначе`, `#КонецЕсли`
и английские `#If ... Then`, `#ElsIf ... Then`, `#Else`, `#EndIf`:

```bsl
#Если Клиент И Не Сервер Тогда
    // #Импорт Побочное.bsl
#Иначе
    // #Импорт Серверное.bsl
#КонецЕсли

#If (AtClient Or Client) And Not AtServer Then
    Сообщить(Побочное.Сумма());
#ElsIf Server Then
    // Этот текст исключен из клиентской программы.
    &AtServer
    Procedure ServerOnly()
        UnsupportedServerAPI();
    EndProcedure
#Else
    Сообщить("Другой контекст");
#EndIf
```

- `Клиент` / `Client` и `НаКлиенте` / `AtClient` истинны;
  `Сервер` / `Server` и `НаСервере` / `AtServer` ложны.
- Поддерживаются вложенные блоки, скобки и операции `Не` / `Not`, `И` / `And`,
  `Или` / `Or` в указанном порядке приоритета. Выбирается первая истинная ветвь.
- Это фиксированный профиль, а не система пользовательских символов:
  неизвестные символы и специальные платформенные режимы (`ТонкийКлиент`,
  `ThinClient`, `WebClient` и прочие) отклоняются с диагностикой. Условия
  проверяются полностью, в том числе в невыбранных ветвях.
- Директивы условной компиляции занимают отдельные строки. Неактивные строки
  не разбираются как BSL: их синтаксис, серверные аннотации и импорты не
  исполняются и не загружаются. Вложенные условные директивы всё равно должны
  быть корректны. Директивы внутри строковых литералов активного кода и
  комментариев не обрабатываются.
- Номера строк и исходный файл сохраняются в диагностике. Незавершенные
  объявления и блоки `#Если` можно продолжать в интерактивной консоли.

Ориентиры: [руководство разработчика 1С, раздел 4.8.1.2](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/)
и [грамматика условий в 1C:EDT](https://edt.1c.ru/dev/edt/2024.2/apidocs/com/_1c/g5/v8/dt/bsl/parseTreeConstruction/BslParsetreeConstructor.html).
В самой платформе [директивы исполнения относятся к модулям форм и команд](https://1c-dn.com/library/using_compilation_directives/);
Yadinassi применяет клиентскую директиву к своим самостоятельным `.bsl`-модулям.
Его фиксированный профиль не воспроизводит файловый режим толстого клиента 1С,
где одновременно доступны клиентские и серверные символы препроцессора.

## Области исходного кода

Поддерживаются `#Область Имя` / `#КонецОбласти` и английские
`#Region Name` / `#EndRegion`. Регистр не важен; открывающую и закрывающую
директивы можно записать на разных языках. Область объединяет исходный код
и не создает новую область видимости переменных или подпрограмм:

```bsl
#Область ПрограммныйИнтерфейс

&НаКлиенте
Функция Ответ(Знач Основание = 40) Экспорт
    #Область Вычисление
    Результат = Основание + 2;
    #КонецОбласти

    Возврат Результат;
КонецФункции

#КонецОбласти

#Область Инициализация
Сообщить(Ответ()); // 42
#КонецОбласти
```

- Имя обязательно: один идентификатор из букв, цифр и `_`, начинающийся с
  буквы или `_`. Ключевые слова поддерживаемого синтаксиса BSL как имена
  отклоняются. `Область`, `Region`, `Client` и другие имена контекстов допустимы.
  Имя не объявляет переменную; одинаковые имена областей не конфликтуют.
- Области могут быть пустыми и вложенными. Закрытие относится к последней
  открытой области; после `#КонецОбласти` имя или выражение не пишется.
- Директивы занимают отдельные строки. Как и для существующих условных
  директив, Yadinassi допускает отступ, пробел после `#` и завершающий
  комментарий `//`. Директивы в комментариях и многострочных строках
  активного кода остаются обычным текстом.
- Область может охватывать несколько полных подпрограмм, операторов или
  находиться внутри одного блока. Она не пересекает границы процедуры,
  функции, ветвей `Если` / `Попытка`, цикла или условной компиляции.
  Область не заменяет `;` между операторами, не разрешает импорт внутри
  подпрограммы и не меняет применение `&НаКлиенте`.
- Незавершенная область запрашивает продолжение ввода в REPL. До ее закрытия
  накопленный код не исполняется. При окончании файла или ввода ошибка
  указывает место открывающей директивы. Остальные номера строк и столбцов,
  включая импортированные модули, сохраняются.

Области и условные директивы можно вкладывать друг в друга, закрывая каждую
конструкцию внутри той же окружающей конструкции:

```bsl
#Область Подключение
#Если Клиент Тогда
    #Область КлиентскиеМодули
    // #Импорт Побочное.bsl
    #КонецОбласти
#Иначе
    // Текст не входит в клиентскую программу.
#КонецЕсли
#КонецОбласти
```

В неактивных ветвях Yadinassi по-прежнему пропускает текст, кроме условных
директив. Поэтому даже некорректные директивы областей там игнорируются и не
могут закрыть область активного кода. Это явно выбранная политика текущего
клиентского препроцессора: проверка некорректных неактивных областей на
нативной платформе 1С пока не выполнена.

### Область с выражением

В позиции выражения поддерживается область с одним полным выражением,
согласно опубликованной грамматике 1C:EDT:

```bsl
Результат =
#Область Значение
    40 + 2
#КонецОбласти
;
Сообщить(Результат); // 42
```

Такая область является одним первичным выражением; внутри перед закрытием
допустима необязательная `;`. Дополнительного узла исполнения или переменной
не создается. Yadinassi следует структуре грамматики EDT: если область
содержит `1 + 2`, а после ее закрытия стоит `* 3`, результат равен `9`.
Этот пограничный случай приоритета пока не сравнивался с нативной 1С.
Произвольное рассечение выражений, списка аргументов или заголовка подпрограммы
директивами не поддерживается.

Основания: [официальное описание директив препроцессора](https://1c-dn.com/library/preprocessor_instructions/),
[руководство разработчика, раздел Grouping](https://1c-dn.com/download-trial/files/guides/developer_guide.pdf),
[пояснение обязательного имени в синтакс-помощнике](https://1c-dn.com/forum/forum25/topic2467/)
и [грамматика области-выражения 1C:EDT](https://edt.1c.ru/dev/edt/2024.2/apidocs/com/_1c/g5/v8/dt/bsl/parseTreeConstruction/BslParsetreeConstructor.RegionPreprocessorBslExpression_Group.html).
Документация описывает области как средство группировки редактора;
диагностика пересечений в Yadinassi опирается на эти ограничения и грамматику
EDT, а не на сравнительный прогон всех ошибок в 1С. Точные нативные правила
неактивных ветвей, необычных пробелов, повторных имен и приоритета выражений
остаются непроверенными. Нативные сценарии, их вывод и компаратор этим
изменением не изменяются; новые тесты написаны независимо.

## Обработка исключений

Поддерживаются `Попытка` / `Try`, `Исключение` / `Except`,
`КонецПопытки` / `EndTry`, `ВызватьИсключение` / `Raise`
и `ОписаниеОшибки()` / `ErrorDescription()`, без учета регистра:

```bsl
Функция Разделить(Знач Делимое, Знач Делитель)
    Если Делитель = 0 Тогда
        ВызватьИсключение "Делитель не должен быть нулем";
    КонецЕсли;
    Возврат Делимое / Делитель;
КонецФункции

Попытка
    Сообщить(Разделить(10, 0));
Исключение
    Сообщить(ОписаниеОшибки());
КонецПопытки;
Сообщить("Работа продолжается");
```

- При ошибке исполнения оставшиеся операторы `Попытка` пропускаются, выполняется
  обработчик, затем программа продолжается после `КонецПопытки`. Если ошибки нет,
  обработчик не выполняется. Допускаются вложенные блоки.
- Обрабатываются ошибки арифметики, типов, индексов, неизвестных имен и вызовов,
  а также явно вызванные исключения. Ошибка из подпрограммы, в том числе экспортной
  подпрограммы импортированного модуля, передается вызывающему обработчику.
  Локальный контекст завершившегося вызова освобождается; изменения переменных
  по ссылке и массивов не откатываются.
- `ВызватьИсключение Выражение;` вычисляет выражение один раз и преобразует
  результат в строку обычным преобразованием `Строка`. Скобки вокруг единственного
  выражения допустимы. Вариант с категорией, кодом и причинами пока не поддерживается.
- `ВызватьИсключение;` без выражения допустим только лексически внутри
  `Исключение`–`КонецПопытки`. Он передает исходную ошибку следующему внешнему
  обработчику, сохраняя файл, строку и столбец возникновения:

```bsl
Попытка
    Попытка
        ВызватьИсключение "Ошибка операции";
    Исключение
        Сообщить(ОписаниеОшибки());
        ВызватьИсключение;
    КонецПопытки;
Исключение
    Сообщить("Операция завершилась ошибкой");
КонецПопытки;
```

- `ОписаниеОшибки()` возвращает диагностику текущего обработчика в формате
  Yadinassi `файл:строка:столбец: сообщение`. Вызываемые из обработчика подпрограммы
  и импортированные модули видят тот же диагностический контекст. Вне обработчика
  Yadinassi возвращает пустую строку; между командами консоли ошибка не сохраняется.
- Согласно руководству 1С, вход во вложенный обработчик теряет информацию о
  родительской ошибке. Yadinassi не восстанавливает эту информацию: после выхода
  из вложенного обработчика `ОписаниеОшибки()` во внешнем дает пустую строку.
  Повторный вызов без выражения в таком состоянии пока явно отклоняется с
  диагностикой ограничения. Сохраните нужный текст **до** вложенного обработчика
  и при необходимости используйте `ВызватьИсключение СохраненныйТекст;`:
  это создаст новую ошибку с новым местом возникновения. Вложенная успешная
  `Попытка`, не вошедшая в `Исключение`, контекст ошибки не меняет.
- `Возврат`, `Прервать` и `Продолжить` не являются ошибками и не перехватываются.
  Выход из обработчика любым из этих способов очищает его контекст.
- Лексические, синтаксические ошибки и ошибки препроцессора не перехватываются.
  Импорты по-прежнему загружаются до исполнения операторов основного модуля;
  `Попытка` вокруг вызова не ловит ошибку первоначальной загрузки импорта.
- В Python API ошибки исполнения представлены `BSLRuntimeError`, подклассом
  `BSLError`. Зарегистрированные функции могут явно вызывать `BSLRuntimeError`;
  прежние `ArithmeticError`, `ValueError`, `TypeError`, `IndexError`, `RecursionError`
  преобразуются в него на границе исполнения. Произвольные ошибки расширений,
  `SystemExit`, `KeyboardInterrupt` и базовый `BSLError` не перехватываются BSL.

`ИнформацияОбОшибке` / `ErrorInfo`, категории, цепочки причин и точное форматирование
диагностики платформы 1С пока не реализованы. Поведение после вложенного обработчика
ограничено описанными правилами и требует дальнейшей проверки на нативной платформе.
Основание для управления потоком и преобразования сообщения:
[руководство разработчика 1С 8.3.27, раздел 4.6.10](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/?sphrase_id=1678862).
Описание расширенной диагностики:
[руководство 1С, информация об ошибках](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_8.3.23_Developer_Guide/Chapter_32._Debugging_and_testing_applications/32.3._Runtime_errors/32.3.3._Error_information/?language=en).
Сравнительный прогон на нативной 1С не выполнялся; тесты проверяют заявленное
подмножество Yadinassi, а не полную совместимость с платформой.

## Сравнение с сохраненным выводом 1С

Корневой набор тестов автоматически находит все `.bsl` непосредственно в
`integrational_tests/tests` и сравнивает их вывод в Yadinassi с соответствующими
`integrational_tests/output/<имя>.out`, полученными пользователем на реальной 1С.
Для сравнения установка 1С не требуется. Запуск из корня репозитория:

```console
python -m unittest discover -s tests -v
```

Только сравнение и проверки самого runner:

```console
python -m unittest discover -s tests -p test_native_outputs.py -v
```

- Список сценариев совпадает с нативным launcher: расширение `.bsl` без учета
  регистра, сортировка по имени без учета регистра и затем по исходному имени.
  Вложенные каталоги не обходятся. Пустой набор и конфликтующие имена дают ошибку.
- Каждый сценарий запускается в отдельном процессе Python с новым `Interpreter`
  и таймаутом 10 секунд. Ошибка разбора, исполнения или таймаут проваливают тест,
  даже если частичный вывод совпал. Диагностика указывает имя сценария; ошибка
  одного сценария не мешает проверить остальные.
- Исходники читаются как UTF-8 с необязательным BOM. Сообщения сериализуются так
  же, как в нативном launcher: CRLF и одиночный CR заменяются на LF, после каждого
  сообщения добавляется один LF. Отсутствие сообщений дает пустой вывод,
  одно пустое сообщение дает один LF.
- Файлы `.out` читаются как UTF-8; для переносимости Git checkout переводы CRLF
  и CR также приводятся к LF. Других преобразований нет: пробелы, табуляция,
  пустые строки, Unicode и последний перевод строки значимы. Начальный BOM
  результата не отбрасывается: это может быть частью первого сообщения.
- Отсутствующий `.out` означает ошибку с требованием генерации на реальной 1С,
  а не пропуск. Наличие соответствующего `.err`, даже пустого, блокирует
  сравнение с частичным или старым результатом. Runner ничего не записывает
  в исходники, `output` или `meta.md` и не запускает нативную генерацию.

После изменения или добавления сценария сначала нужно заново получить его
результат на реальной 1С с помощью существующего `integrational_tests/test_launcher.py`.
Не заменяйте эталон выводом Yadinassi. Текущий `meta.md` содержит версию платформы,
но не хеши сценариев: автоматической проверки свежести `.out` нет, а время файлов
после Git checkout ее не доказывает. Расхождение до повторной нативной генерации
не доказывает ошибку интерпретатора.

Нативный launcher исполняет модуль объекта на сервере; Yadinassi использует
фиксированный клиентский контекст. При добавлении сценариев, зависящих от
директив контекста, это различие нужно учитывать. Совпадение сохраненного вывода
проверяет только конкретные сценарии, а не полную совместимость с платформой.
Собственные проверки runner используют временные синтетические файлы;
они не являются новыми эталонами 1С.

## Базовые строковые функции

Добавлены функции с русскими и английскими именами; регистр имени не важен:

| Функция | Английское имя | Результат |
| --- | --- | --- |
| `Лев(Строка, Количество)` | `Left` | Начало строки |
| `Прав(Строка, Количество)` | `Right` | Конец строки |
| `Сред(Строка, Начало, Количество)` | `Mid` | Подстрока с позиции, считая от 1 |
| `Найти(Строка, Подстрока)` | `Find` | Позиция первого вхождения от 1 или 0 |
| `СтрЗаменить(Строка, Подстрока, Замена)` | `StrReplace` | Замена всех неперекрывающихся вхождений |
| `СокрЛ(Строка)` | `TrimL` | Удаление пробельных символов слева |
| `СокрП(Строка)` | `TrimR` | Удаление пробельных символов справа |
| `СокрЛП(Строка)` | `TrimAll` | Удаление пробельных символов с обоих краев |
| `ПустаяСтрока(Строка)` | `IsBlankString` | Отсутствие непробельных символов |
| `ВРег(Строка)` / `НРег(Строка)` | `Upper` / `Lower` | Изменение регистра |
| `СтрРазделить(Строка, Разделители, ВключатьПустые)` | `StrSplit` | Новый массив строк |
| `СтрСоединить(Массив, Разделитель)` | `StrConcat` | Объединение элементов массива |

```bsl
Сообщить(Лев("Яблоко", 3));                 // Ябл
Сообщить(Прав("Яблоко", 2));                // ко
Сообщить(Сред("Яблоко", 3));                // локо
Сообщить(Найти("Яблоко", "лок"));           // 3
Сообщить(СтрЗаменить("а-б-а", "а", "ёж")); // ёж-б-ёж

Части = СтрРазделить(" ёж,;бор,,лес ", ",;", Ложь);
Для Индекс = 0 По Части.ВГраница() Цикл
    Части[Индекс] = ВРег(СокрЛП(Части[Индекс]));
КонецЦикла;
Сообщить(СтрСоединить(Части, " / "));       // ЁЖ / БОР / ЛЕС
```

Правила текущей реализации:

- Строковые аргументы преобразуются тем же способом, что `Строка`: например,
  `СокрЛП(12.50)` дает `"12.5"`, `ВРег(Истина)` — `"ДА"`,
  `ПустаяСтрока(Неопределено)` — `Истина`. Это относится и к существующей
  `СтрДлина` / `StrLen`, которая раньше отклоняла нестроковый аргумент.
  Элементы `СтрСоединить` также преобразуются в строку; принимаются обычный
  и фиксированный массивы.
- Числовые позиции и длины преобразуются через `Число`, дробная часть отбрасывается
  к нулю без промежуточного `float`. Нечисловые значения вызывают ошибку.
  `Лев` и `Прав` при количестве ≤ 0 возвращают пустую строку; при количестве
  больше длины — всю строку. В `Сред` начало ≤ 0 считается равным 1;
  начало за концом дает пустую строку. Неуказанное или отрицательное количество
  означает остаток строки, нулевое — пустую строку; слишком большое обрезается.
- Поиск и замена чувствительны к регистру и не используют регулярные выражения
  или Unicode-нормализацию. `Найти` с пустой подстрокой дает 1, в том числе для
  пустого источника; `СтрЗаменить` с пустой подстрокой оставляет источник прежним.
  Вставленная замена не просматривается повторно.
- Сокращение и проверка пустоты используют фиксированный набор Unicode White_Space:
  U+0009–U+000D, U+0020, U+0085, U+00A0, U+1680, U+2000–U+200A, U+2028–U+2029,
  U+202F, U+205F, U+3000. Внутренние пробелы сохраняются; U+200B, U+FEFF,
  U+001C–U+001F и нулевой символ пробелами не считаются. Это явный набор, а не
  расширенный предикат пробельности Python.
- В `СтрРазделить` каждый символ разделителей действует отдельно, поэтому
  `СтрРазделить("а::б", "::")` дает `"а"`, `""`, `"б"`.
  По умолчанию `ВключатьПустые = Истина`; начальные, конечные и соседние
  разделители сохраняют пустые элементы. При `Ложь` удаляются только пустые
  строки, но не строки из пробелов. Пустой источник дает массив из одной пустой
  строки либо пустой массив при `Ложь`; пустой набор разделителей не делит строку.
  Явное `Неопределено` в третьем аргументе действует как `Ложь`, а не как пропуск
  аргумента. Это локальное правило `СтрРазделить`, без изменения общего
  преобразования `Неопределено` в булево значение.
- `СтрСоединить` по умолчанию соединяет без разделителя. Явный разделитель
  вставляется целиком только между элементами, включая пустые; пустой массив
  дает пустую строку. Входной массив не изменяется, каждый `СтрРазделить` создает
  самостоятельный изменяемый массив.
- Необязательные аргументы можно не передавать в конце вызова. Явно пропущенные
  позиции между запятыми у встроенных функций пока по-прежнему отклоняются.
  Явное `Неопределено` не означает пропуск числовой длины; у `СтрРазделить`
  для третьего аргумента действует отдельное правило выше.
  Ошибки количества аргументов и преобразования перехватываются `Попытка`.

### UTF-16 и границы совместимости

Длина, позиции, срезы, поиск, замена и символы-разделители теперь согласованы
по 16-битным кодовым единицам UTF-16. Например:

```bsl
Сообщить(СтрДлина("A🙂B"));                  // 4
Сообщить(Сред("A🙂B", 2, 2));                // 🙂
Сообщить(Найти("A🙂B", "B"));               // 4
Сообщить(Лев("🙂", 1) + Прав("🙂", 1));      // 🙂
```

Срез может содержать отдельную половину суррогатной пары. `+` и `СтрСоединить`
восстанавливают целый символ при соединении двух половин. Вывод отдельной
половины на UTF-8-консоль может вызвать ошибку кодировки; вывод корректной пары
проверен в исходном и автономном интерпретаторе. Разделитель вне BMP состоит из
двух кодовых единиц, каждая действует отдельно. Графемные кластеры не выделяются:
буква и комбинируемый знак считаются отдельно.

Официальное руководство описывает хранение строк в UTF-16:
[раздел 4.3.6 руководства 1С 8.3.27](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/).
Примеры обычных операций и их применения:
[разбор HTTP-данных](https://its.1c.ru/db/content/metod8dev/src/developers/platform/demo/i8105574.htm),
[различие пустых значений](https://its.1c.ru/db/content/metod8dev/src/developers/platform/metod/types/i8102614.htm),
[СокрЛП с числовым аргументом](https://its.1c.ru/db/content/metod8dev/src/developers/platform/metod/applied/i8102588.htm),
[новые функции строк](https://wonderland.v8.1c.ru/blog/novye-funktsii-raboty-so-strokami/).
Часть граничных решений дополнительно сопоставлена с открытой реализацией
[OneScript](https://github.com/EvilBeaver/OneScript/blob/6f12dbdd557a768c24608927b72f3b6e63288d70/src/ScriptEngine/Machine/MachineInstance.cs)
и [ее строковой библиотекой](https://github.com/EvilBeaver/OneScript/blob/6f12dbdd557a768c24608927b72f3b6e63288d70/src/OneScript.StandardLibrary/StringOperations.cs).
Это вторичная реализация языка, а не доказательство поведения нативной 1С.
Код и тесты написаны самостоятельно.

Нативный `strings.out`, добавленный владельцем репозитория, подтверждает
зафиксированные сценариями операции UTF-16, пустые параметры поиска/разделения,
отдельные дробные/отрицательные срезы и неявные преобразования (см. ниже).
Это конечный набор примеров: полный диапазон чисел, набор пробельных символов
и все варианты преобразований на платформе пока не проверены.
`ВРег` / `НРег` используют посимвольное простое преобразование регистра Unicode,
без расширения одного символа в несколько и без контекста соседних букв.
Например, нативные результаты `ВРег("Straße") = "STRAßE"` и `НРег("İ") = "i"`
отличаются от полных преобразований Python и теперь воспроизводятся.
Опорные определения — [простые преобразования регистра Unicode](https://www.unicode.org/faq/casemap_charprop.html)
и поля 12/13 [UnicodeData](https://www.unicode.org/Public/15.1.0/ucd/UnicodeData.txt).
Односимвольные отображения берет база Unicode установленного Python;
альтернативы расширяющим отображениям заданы по Unicode 15.1. Это политика
интерпретатора, согласованная с наблюдаемыми примерами, а не доказательство
всех региональных правил сеанса 1С или всех версий Unicode.
Булевы представления сохраняют прежние правила Yadinassi, а десятичный
разделитель числовых представлений уточнен ниже по нативному опыту владельца.
Полного регионального форматирования 1С пока нет. Это описание проверяемого поведения
интерпретатора, а не заявление полной совместимости с платформой.

`СтрНайти` с направлением и номером вхождения, системное перечисление
`НаправлениеПоиска`, `ТРег`, `Символ` и `КодСимвола` в этот блок не входят.
Существующее правило конфликта имени импорта со встроенной функцией применяется
и к новым именам, например `Left.bsl`; такой модуль нужно переименовать.

## Структура и именованные свойства

Добавлен тип `Структура` / `Structure`:

```bsl
Данные = Новый Структура("Имя,Количество,Комментарий", "ёж", 2);
Данные.Имя = "бор";
Данные["Количество"] = Данные.Количество + 1;
Сообщить(Данные.Имя);                         // бор
Сообщить(Данные["количество"]);              // 3
Сообщить(Данные.Комментарий = Неопределено);  // Да
Данные.Вставить("Готово", Истина);
Сообщить(Данные.Количество());                // 4, вызов метода
```

- `Новый Структура`, `Новый Структура()` и `New Structure` создают пустую
  коллекцию. В конструкторе можно передать строку имен через запятую и значения
  по порядку. Неуказанные значения равны `Неопределено`.
- Краевые пробельные символы каждого имени в списке удаляются тем же способом,
  что `СокрЛП`; пустые части списка пропускаются и не занимают позицию значения.
  Например, `Новый Структура(", А,, Б,", 1, 2)` содержит `А = 1`, `Б = 2`.
  Повторное имя заменяет прежнее значение по тем же правилам, что `Вставить`.
  Лишние значения конструктора игнорируются, но выражения всех переданных
  аргументов предварительно вычисляются слева направо.
- Имена свойств сравниваются без учета регистра. Чтение и запись через точку
  или строковый индекс обращаются к одной ячейке. Числовой индекс не означает
  позицию: у структуры индексом служит имя свойства.
- Присваивание меняет только существующее свойство. Для добавления используйте
  `Вставить`; чтение и запись отсутствующего свойства вызывают перехватываемую
  ошибку. Вложенные цели вроде `Данные.Детали["Сумма"] = 10` поддерживаются.
  `Вставить` существующего имени обновляет также написание ключа: после
  `Данные.Вставить("имя", Значение)` обход возвращает `"имя"`.
  Присваивание через точку или индекс само по себе написание не меняет.
- Имена методов отделены от имен свойств: `Данные.Количество` читает свойство,
  а `Данные.Количество()` вызывает метод, даже если такое свойство существует.
  Сам метод структуры нельзя сохранить в переменную без вызова.

| Метод | Английское имя | Действие |
| --- | --- | --- |
| `Вставить(Имя, Значение)` | `Insert` | Добавляет свойство или заменяет значение; без второго аргумента записывает `Неопределено` |
| `Удалить(Имя)` | `Delete` | Удаляет свойство; корректное отсутствующее имя ничего не меняет |
| `Очистить()` | `Clear` | Удаляет все свойства |
| `Количество()` | `Count` | Возвращает число свойств |
| `Свойство(Имя, Результат)` | `Property` | Проверяет наличие и при необходимости записывает значение в выходную переменную |

### Выходной параметр Свойство

```bsl
Перем Найденное;
Данные = Новый Структура("Цена", 150);
Если Данные.Свойство("цена", Найденное) Тогда
    Сообщить(Найденное);                    // 150
КонецЕсли;
Сообщить(Данные.Property("Нет", Найденное)); // Нет
Сообщить(Найденное = Неопределено);           // Да
Сообщить(Данные.Свойство("Цена"));           // Да, без выходного параметра
```

Результат метода — булево значение. Для отсутствующего свойства выходная
переменная сбрасывается в `Неопределено`; свойство с таким значением все равно
считается существующим. Некорректное имя вызывает ошибку и выход не изменяет.
В `Свойство` краевые обычные пробелы U+0020 удаляются перед поиском, поэтому
`Данные.Свойство(" Цена ", Найденное)` находит `Цена` и заполняет выход.
Подтверждено только это правило. В текущей реализации другие пробельные символы
не обрезаются; их поведение в нативной `Свойство` отдельно не проверялось.
Объекты передаются без копирования: массив или структура на выходе сохраняют
идентичность исходного значения.

Для выходного аргумента действуют существующие ограничения передачи по ссылке:
изменяется только предварительно объявленная или уже присвоенная переменная
без скобок. Сам вызов не объявляет неизвестные переменные. Ссылки работают
через цепочки обычных и экспортных подпрограмм; выход в параметр `Знач` меняет
его локальную ячейку. Литералы и вычисляемые выражения служат временными
значениями, их изменение не сохраняется. `(Переменная)`, `Массив[0]` и
`Объект.Свойство` в этой позиции по-прежнему явно отклоняются, как и у обычных
параметров без `Знач`. Запись свойств оператором присваивания это ограничение
не снимает. Остальные встроенные функции продолжают получать значения.

### Обход структуры

```bsl
Данные = Новый Структура("Имя,Цена", "ёж", 150);
Для Каждого Элемент Из Данные Цикл
    Сообщить(Элемент.Ключ + ": " + Строка(Элемент.Значение));
КонецЦикла;
```

Обход возвращает объекты `КлючИЗначение` с доступными только для чтения
свойствами `Ключ` / `Key` и `Значение` / `Value`. Значение-объект остается
изменяемым: например, `Элемент.Значение.Добавить(1)` меняет вложенный массив.
Прямое создание `КлючИЗначение` не реализовано. Строковые представления типов —
`"Структура"` и `"КлючИЗначение"`.

В Yadinassi обход идет в порядке добавления уникальных имен; каждый элемент
сохраняет ключ и значение на момент его получения. Изменение значения через
структуру не переписывает ранее полученную пару, но учитывается при последующем
получении элемента. Добавление или удаление имен, включая непустую `Очистить`,
приводит к перехватываемой ошибке при следующем шаге этого обхода. Само изменение
не откатывается; после `Прервать` обход больше не продолжается. Это явные правила
интерпретатора: руководство 1С оставляет поведение обхода при изменении элементов
неопределенным. Порядок и обновление значений не заявлены как нативная гарантия.

### Проверки и границы совместимости

Имена должны быть строками. Как в текущем лексере Yadinassi, первый символ —
буква или `_`, остальные — буквы, цифры либо `_`. Ключи, совпадающие с ключевыми
словами языка, доступны через строковый индекс. Пробельные края удаляются
в списке конструктора; `Свойство` отдельно удаляет краевые U+0020.
Имена в `Вставить`, `Удалить` и строковых индексах не обрезаются.
Неявное преобразование нестроковых имен, необычные Unicode-идентификаторы и
региональные правила сравнения 1С пока не воспроизведены: сравнение использует
`casefold` Python. Копирование из `ФиксированнаяСтруктура` описано
в разделе фиксированных коллекций ниже; `Соответствие` — в отдельном разделе.
Пропущенные позиции между запятыми
у встроенных методов и конструкторов по-прежнему не поддерживаются.

Официальные основания: [учебный курс 1Ci, системные классы](https://kb.1ci.com/1C_Enterprise_Platform/Tutorials/1C_Enterprise_Platform_Training_Course_-_Junior_Application_Developer_Level/Module_3._1C_script_language_basics/Episode_5._System_classes/?language=en)
описывает ключи, замену через `Insert`, доступ через точку/индекс и обход;
[руководство разработчика 8.3.27](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/),
разделы 4.2.4.3–4.2.4.5, 4.7.1 и 4.7.5 — регистр имен, доступ к свойствам
и ограничения изменения коллекций при обходе.
Граничные случаи конструктора, отсутствующий выход `Property` и пары обхода

## Соответствие и произвольные ключи

Добавлен изменяемый тип `Соответствие` / `Map`. Пустую коллекцию создают
`Новый Соответствие`, `Новый Соответствие()` и `New Map()`.

```bsl
Цены = Новый Соответствие;
Цены.Вставить("Чай", 120);
Цены["Кофе"] = 180;
Цены["Чай"] = Цены.Получить("Чай") + 10;
Сообщить(Цены["Чай"]);                      // 130
Сообщить(Цены.Количество());                 // 2
Сообщить(Цены["Нет"] = Неопределено);        // Да
Цены.Удалить("Нет");                         // ничего не меняет
Цены.Вставить("Без цены");                   // значение Неопределено
```

| Метод | Английское имя | Действие |
| --- | --- | --- |
| `Вставить(Ключ, Значение)` | `Insert` | Добавляет пару или заменяет значение; без второго аргумента записывает `Неопределено` |
| `Получить(Ключ)` | `Get` | Возвращает значение, а для отсутствующего ключа — `Неопределено` |
| `Удалить(Ключ)` | `Delete` | Удаляет пару; отсутствующий ключ ничего не меняет |
| `Очистить()` | `Clear` | Удаляет все пары, после чего коллекцию можно использовать снова |
| `Количество()` | `Count` | Возвращает число пар |

Индекс — сам ключ, а не позиция. Чтение через `[]` и `Получить` использует
одни данные; присваивание через `[]` добавляет отсутствующий ключ или заменяет
значение существующего. Чтение отсутствующего ключа коллекцию не меняет.
По результату чтения нельзя отличить отсутствующий ключ от сохраненного
`Неопределено`: для такой проверки можно перебрать пары.

Свойств, доступных через точку, у соответствия нет. Даже строковые ключи
`"Количество"`, `"Count"` или `"__class__"` остаются обычными ключами и
доступны через индекс, независимо от вызовов методов. Имена типа, методов и
свойств пары обхода поддерживают русские/английские варианты без учета регистра.
Это не меняет регистр самих строковых ключей.

### Сравнение ключей и общие ссылки

Поддерживаются все уже реализованные значения: строки, числа, булевы значения,
`Неопределено`, обычные и фиксированные массивы, структуры и соответствия,
пары обхода и значения `Тип`
(см. следующий раздел).

- Разные примитивные типы не смешиваются: `Истина`, `1` и `"1"` — три ключа;
  `Ложь` и `0` также различаются.
- Числа сравниваются по числовому значению: `1` и `1.00`, а также `0` и `-0`
  обозначают один ключ. Строки сравниваются с учетом регистра, без обрезки
  пробелов или Unicode-нормализации.
- Изменяемые объекты сравниваются по идентичности. Два отдельных массива с
  одинаковыми элементами — разные ключи. Изменение массива, который уже служит
  ключом, не мешает получить значение по тому же объекту. Собственное
  соответствие также может быть ключом или значением.
- Фиксированные коллекции тоже служат ключами по идентичности: повторная
  вставка той же ссылки заменяет ее значение, отдельный снимок того же
  содержимого создает другой ключ. Копирование соответствия сохраняет ключи.
- Пары `КлючИЗначение` в текущем интерпретаторе тоже служат ключами по
  идентичности: новая пара с теми же полями не равна ранее полученной паре.
  Это правило пока отдельно не проверено на нативной платформе.
- Ключи и значения-объекты хранятся без копирования. Это сохраняется при
  присваивании, передаче параметра `Знач` и возврате из экспортной функции.
  Саму переменную параметр `Знач` по-прежнему не перепривязывает у вызывающего.

```bsl
Данные = Новый Соответствие;
Данные.Вставить(Истина, "булево");
Данные.Вставить(1, "число");
Данные.Вставить("Имя", "верхний регистр");
Данные.Вставить("имя", "нижний регистр");
Данные[Неопределено] = "пустой ключ";
Ключ = Новый Массив;
Данные[Ключ] = "тот же объект";
Ключ.Добавить(7);
Сообщить(Данные[Ключ]);                       // тот же объект
Сообщить(Данные[Новый Массив] = Неопределено); // Да
Сообщить(Данные.Количество());                // 6
```

### Обход соответствия

```bsl
Цены = Новый Соответствие;
Цены["Чай"] = 120;
Цены["Кофе"] = 180;
Сумма = 0;
Для Каждого Пара Из Цены Цикл
    Сумма = Сумма + Пара.Значение;
КонецЦикла;
Сообщить(Сумма);                             // 300
```

Каждая итерация возвращает `КлючИЗначение` с доступными только для чтения
`Ключ` / `Key` и `Значение` / `Value`; ключ может быть любого поддержанного
типа. Присваивание свойствам пары вызывает перехватываемую ошибку. Объект,
полученный через свойство, остается изменяемым. Строковое представление
соответствия — `"Соответствие"`, пары — `"КлючИЗначение"`.

Порядок обхода не следует использовать в алгоритме или ожиданиях теста:
платформа 1С не гарантирует его. В текущем Yadinassi пара сохраняет ссылки
на ключ и значение в момент ее получения. Замена значения существующего
ключа допускается и видна при последующем получении пары; уже полученная пара
не переписывается. Удаление отсутствующего ключа не нарушает обход.
Добавление или удаление ключей и очистка непустого соответствия вызывают
перехватываемую ошибку при следующем шаге текущего обхода. Само изменение
сохраняется; после `Прервать` следующего шага нет. Это диагностическая граница
интерпретатора, а не обещание воспроизвести нативное поведение изменения состава.

### Основания и ограничения

Официальный [урок 1Ci о системных классах](https://kb.1ci.com/1C_Enterprise_Platform/Tutorials/1C_Enterprise_Platform_Training_Course_-_Junior_Application_Developer_Level/Module_3._1C_script_language_basics/Episode_5._System_classes/?language=en)
описывает произвольные ключи соответствия, индексный доступ и обход.
[Модель типов 1С, раздел 4.3.1](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/)
различает сравнение неизменяемых значений и идентичность изменяемых объектов;
применение этого правила к объектным ключам — вывод из общей модели типов.
[Правила сравнения строк](https://its.1c.ru/db/content/metod8dev/src/developers/platform/metod/types/i8102615.htm)
указывают учет регистра во встроенном языке.
Поддержка `Неопределено` как ключа появилась в
[платформе 8.3.21](https://1c-dn.com/1c_enterprise/new_features_in_version_8_3_21/).
[Рекомендации по обходу коллекций](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Standards/1C_Enterprise_script/)
отдельно предупреждают о непредсказуемом порядке соответствия и изменении
коллекции во время обхода.

`ФиксированноеСоответствие` и конструктор копирования описаны ниже.
Еще не реализованные типы ключей в этот блок не входят. У коллекции нет метода `Установить`:
для записи служат `Вставить` и `[]`. Пропуски позиций между запятыми
во встроенных вызовах по-прежнему отклоняются. Передача индексированной ячейки
в изменяемый параметр подпрограммы пока не поддерживается; можно передать
значение через `Знач` или записать результат отдельным присваиванием.
Объекты, переданные расширением Python, используются как ключи по идентичности,
кроме точных встроенных типов `str`, `Decimal`, `bool`, `None` и описанных
ниже значений `BSLType`. Фиксированные коллекции используют ту же идентичность
объектных ключей, без вызова Python-методов сравнения и хеширования расширений.
Ключ у `Вставить`, `Получить` и `Удалить` в текущем подмножестве обязателен.
Точная обязательность параметров `Вставить` еще требует отдельной нативной
проверки. Сохраненный результат `collections.bsl` подтверждает смешанные ключи,
объектную идентичность, отсутствие вставки при чтении отсутствующего ключа,
удаление отсутствующего ключа и чтение пар без предположения о порядке.

Тесты этого блока проверяют контракт интерпретатора, включая смешанные ключи,
общие ссылки, импорт, ошибки, обход и воспроизводимые случайные операции.
Нативные наблюдения и границы их покрытия описаны в последнем разделе.
Код, тесты и примеры написаны самостоятельно.

## Тип и ТипЗнч

Добавлены `Тип(ИмяТипа)` / `Type(TypeName)` и `ТипЗнч(Значение)` /
`TypeOf(Value)`. Обе функции возвращают самостоятельное неизменяемое значение
типа `Тип`, которое можно сохранить в переменной, передать в подпрограмму,
вернуть из нее или поместить в коллекцию. `ТипЗнч` определяет тип текущего
значения, а не тип объявления переменной.

```bsl
Функция Описание(Знач Значение)
    Если ТипЗнч(Значение) = Тип("Строка") Тогда
        Возврат "текст: " + Значение;
    ИначеЕсли ТипЗнч(Значение) = Тип("Массив") Тогда
        Возврат "элементов: " + Значение.Количество();
    КонецЕсли;
    Возврат "другой тип";
КонецФункции

Данные = Новый Массив;
Данные.Добавить(42);
Сообщить(Описание(Данные));             // элементов: 1
Сообщить(Описание("пример"));          // текст: пример
Сообщить(ТипЗнч(42) = Тип("Число"));   // Да
Сообщить(ТипЗнч(Истина) = ТипЗнч(1));  // Нет
Сообщить(ТипЗнч(Тип("Число")) = Тип("Тип")); // Да
```

Поддержан следующий закрытый набор имен:

| Русское имя | Английское имя | Значения |
| --- | --- | --- |
| `Неопределено` | `Undefined` | `Неопределено`, в том числе начальное значение `Перем` |
| `Булево` | `Boolean` | `Истина`, `Ложь` |
| `Число` | `Number` | Все уже поддержанные числа |
| `Строка` | `String` | Строки, включая пустую |
| `Массив` | `Array` | Изменяемые массивы |
| `Структура` | `Structure` | Изменяемые структуры |
| `Соответствие` | `Map` | Изменяемые соответствия |
| `ФиксированныйМассив` | `FixedArray` | Фиксированные массивы |
| `ФиксированнаяСтруктура` | `FixedStructure` | Фиксированные структуры |
| `ФиксированноеСоответствие` | `FixedMap` | Фиксированные соответствия |
| `КлючИЗначение` | `KeyAndValue` | Пары, полученные при обходе структуры или соответствия |
| `Тип` | `Type` | Результаты `Тип` и `ТипЗнч` |

Имена функций и перечисленные имена типов принимают русские и английские
варианты без учета регистра. Например, `Type("NUMBER") = Тип("число")`.
Строковые имена сопоставляются через `casefold` Python; региональные правила
и необычные Unicode-эквивалентности отдельно не воспроизводятся.

### Сравнение, хранение и представление

Значения типов сравниваются операторами `=` и `<>`. Русский/английский вариант
имени, регистр и место получения значения, включая импортированный модуль,
не меняют его идентичность. Тип отличается от строки с его названием:
`Тип("Число") = "Число"` дает `Ложь`. Числа, строки и булевы значения
не смешиваются при определении типа.

`Найти` у массива распознает равные значения типов. В соответствии они
служат ключами по значению: повторная запись через равный тип заменяет
существующую пару. Строка с тем же представлением остается отдельным ключом.

```bsl
Подписи = Новый Соответствие;
Подписи[Тип("Число")] = "числовое значение";
Подписи[Type("Number")] = "число"; // заменяет ту же пару
Подписи["Число"] = "строковый ключ";
Сообщить(Подписи[ТипЗнч(42)]);      // число
Сообщить(Подписи.Количество());     // 2

Для Каждого Пара Из Подписи Цикл
    Сообщить(ТипЗнч(Пара) = Тип("КлючИЗначение")); // Да
КонецЦикла;
```

`Строка`, `Сообщить` и конкатенация со строкой слева показывают русское
представление из таблицы, в том числе `"Тип"` для `Тип("Тип")`.
Yadinassi пока не выбирает язык интерфейса: английский вариант вызова тоже
выводит русское представление. Для проверки типа нужно сравнивать сами
значения типов, а не их отображаемые строки.

### Границы этого этапа

Обе функции требуют ровно один аргумент; явное `Неопределено` допустимо
для `ТипЗнч`, а пропуск позиции между запятыми не поддерживается.
`Тип` принимает именно строку без неявного преобразования и обрезки пробелов.
Неизвестное, пустое или еще не поддержанное имя вызывает перехватываемую
ошибку, а не возвращает `Неопределено`. Это также относится к именам
`Дата`, `Null`, `ОписаниеТипов` и прикладным типам
метаданных. Они не становятся доступными благодаря этой функции.

У значений типа нет доступных полей, методов, индексов или вызова.
Сортировка через `<`, `<=`, `>` и `>=`, арифметика и преобразование типа
в число или булево значение отклоняются. `Новый Тип(...)`, создание
`КлючИЗначение` напрямую и динамический `Новый (ВыражениеТипа, ...)`
не добавлены. Прежние именованные конструкторы коллекций работают как раньше.

Регистрация конструктора Python через `Interpreter.register_type` не создает
описатель типа для `Тип`/`ТипЗнч`. Пользовательские объекты Python, подклассы
встроенных реализаций и ссылки на встроенные функции остаются за границей
этого набора; `ТипЗнч` сообщает об этом без рефлексии по Python-атрибутам.

Официальные [рекомендации 1Ci о значениях и типах](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Standards/Values_and_types/?language=en)
описывают получение и сравнение значений `Тип` и зависимость их представлений
от языка интерфейса. [Руководство разработчика 8.3.27](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/),
разделы 4.2.4.3–4.2.4.4, 4.3.7 и 4.5.3, описывает имена на двух языках,
тип `Тип` и допустимые операции сравнения. Проверка типа перед обработкой
строки или структуры также встречается в
[БСП 3.1](https://github.com/1c-syntax/ssl_3_1/blob/da8aa1fcef273f6e61bbb7ec9ea3107cac32cabc/src/cf/CommonModules/GoogleПереводчик/Ext/Module.bsl)
(CC BY 4.0); здесь использован только общий прием, код и тесты написаны
самостоятельно.

Строгость аргумента-имени, его пробелов/регистра и диагностик закреплена тестами
текущего подмножества; отдельного нативного прогона этих граничных случаев еще
нет. Типы коллекций и использование равных значений `Тип` как одного ключа
подтверждены результатом расширенного `collections.bsl`, описанным в последнем
разделе. Это не покрывает все допустимые имена и варианты аргументов.


## Фиксированные коллекции

Добавлены `ФиксированныйМассив` / `FixedArray`, `ФиксированнаяСтруктура` /
`FixedStructure` и `ФиксированноеСоответствие` / `FixedMap`. Имена конструкторов
и методов принимают русские и английские варианты без учета регистра.
`Тип` / `ТипЗнч` различают фиксированные и изменяемые коллекции; `Строка`,
`Сообщить` и консоль используют русские представления новых типов.

### Создание и чтение

- `Новый ФиксированныйМассив(Массив)` требует один изменяемый массив.
  Сохраняется его текущий набор элементов; изменения исходного массива после
  создания не меняют состав и ячейки фиксированного. Доступны `[]`,
  `Количество` / `Count`, `ВГраница` / `UBound`, `Получить` / `Get`,
  `Найти` / `Find` и обход значений в порядке индексов с нуля. Для пустого
  массива верхняя граница равна `-1`; ненайденное значение дает `Неопределено`.
- `Новый ФиксированнаяСтруктура(Структура)` копирует текущие имена и значения
  изменяемой структуры. Также доступны пустой конструктор и строка имен с
  позиционными значениями, как у `Структура`. Недостающие значения заполняются
  `Неопределено`, лишние вычисляются и игнорируются. Имена, включая их текущее
  написание, проверяются и сопоставляются по правилам обычной структуры.
  Доступны чтение через точку/строковый индекс, `Количество` / `Count`,
  `Свойство` / `Property` и обход пар `КлючИЗначение`.
- `Новый ФиксированноеСоответствие(Соответствие)` требует одно изменяемое
  соответствие. Доступны `[]`, `Получить` / `Get`, `Количество` / `Count`
  и обход пар `КлючИЗначение`. Сохраняются правила ключей обычного соответствия:
  точные строки с учетом регистра, раздельные число/булево, `Неопределено`,
  значения `Тип`, идентичность обычных и фиксированных объектных ключей.
  При отсутствующем ключе `Получить` возвращает `Неопределено`, но индексатор
  `[]` вызывает перехватываемую ошибку. Ни один способ не создает запись.
  Существующая запись со значением `Неопределено` читается обоими способами.

```bsl
Исходный = Новый Массив;
Исходный.Добавить("ёж");
Снимок = Новый ФиксированныйМассив(Исходный);
Исходный[0] = "бор";
Сообщить(Снимок[0]);                       // ёж
Сообщить(Снимок.Найти("ёж"));              // 0
Сообщить(ТипЗнч(Снимок) = Тип("FixedArray")); // Да

Карточка = Новый ФиксированнаяСтруктура("Имя,Count", "ёж", 7);
Перем Имя;
Сообщить(Карточка.Свойство("имя", Имя));    // Да
Сообщить(Имя);                            // ёж
Сообщить(Карточка.Count);                  // 7: свойство
Сообщить(Карточка.Count());                // 2: метод

Данные = Новый Соответствие;
Данные[Тип("Число")] = "числовой ключ";
Справочник = Новый ФиксированноеСоответствие(Данные);
Данные.Очистить();
Сообщить(Справочник[ТипЗнч(42)]);           // числовой ключ
Для Каждого Пара Из Справочник Цикл
    Сообщить(Пара.Ключ);
КонецЦикла;
```

`Свойство` принимает необязательную выходную переменную. В текущем подмножестве
найденное значение записывается туда по ссылке, при отсутствии имени записывается
`Неопределено`. Переменную нужно объявить заранее. Передача свойства,
индексированной ячейки или переменной в скобках как изменяемого выхода по-прежнему
отклоняется; вычисляемое выражение не имеет выходного хранилища. Метод и поле
с одинаковым именем не мешают друг другу: точка без вызова читает поле, вызов
выбирает метод. Вызов отсутствующего метода не превращается в вызов свойства.

Присваивание ячейке фиксированной коллекции или свойству фиксированной структуры
вызывает перехватываемую ошибку. Методы добавления, вставки, установки, удаления
и очистки у фиксированных коллекций не предоставляются. Пары обхода также
сохраняют запрет записи в `Ключ` и `Значение`. Внутренние атрибуты Python
не открываются через BSL.

### Вложенные значения и обратные конструкторы

Фиксация структуры и соответствия копирует только их собственные ячейки.
Вложенные изменяемые объекты не замораживаются: они сохраняют свои ссылки,
и вызов их методов виден через все содержащие их коллекции. Фиксированный
массив также сохраняет ссылки на вложенные структуры и соответствия.
Самоссылка исходной структуры/соответствия продолжает указывать на исходный
изменяемый объект. Это снимок верхнего уровня, а не глубокая заморозка графа.

При создании фиксированного массива непосредственно вложенные изменяемые
массивы рекурсивно преобразуются в фиксированные. Изменения исходного листа
после фиксации не затрагивают снимок, а запись через снимок отклоняется.
Рекурсия идет только по элементам-массивам: структуры, соответствия и уже
фиксированные элементы сохраняют ссылки, их содержимое не обходится.

```bsl
Строки = Новый Массив;
Настройки = Новый ФиксированнаяСтруктура("Строки", Строки);
Настройки.Строки.Добавить("добавлено");
Сообщить(Строки.Количество());             // 1

Копия = Новый Структура(Настройки);
Копия.Вставить("Название", "редактируемая копия");
Сообщить(Настройки.Свойство("Название"));  // Нет
```

Добавлены обратные конструкторы `Новый Массив(ФиксированныйМассив)`,
`Новый Структура(ФиксированнаяСтруктура)` и
`Новый Соответствие(ФиксированноеСоответствие)`. Каждый создает отдельную
изменяемую коллекцию; ее записи можно менять независимо от фиксированной.
Структура и соответствие копируются поверхностно. Массив рекурсивно преобразует
непосредственные элементы типа `ФиксированныйМассив` в новые обычные массивы,
но не обходит содержимое структур и соответствий. Две позиции с одной ссылкой
на фиксированный массив получают отдельные изменяемые копии: запись в первую
не меняет вторую и исходный фиксированный массив. Это подтверждено нативным
опытом `nested.copy-back-second`.

```bsl
СтрокаМассива = Новый Массив(1);
СтрокаМассива[0] = 10;
Внешний = Новый Массив;
Внешний.Добавить(Новый ФиксированныйМассив(СтрокаМассива));
Матрица = Новый ФиксированныйМассив(Внешний);
Копия = Новый Массив(Матрица);
Копия[0][0] = 20;
Сообщить(Матрица[0][0]);                   // 10
Сообщить(ТипЗнч(Копия[0]) = Тип("Массив")); // Да
```

### Равенство, ключи и строковое соединение

`=` и `<>` сравнивают фиксированные коллекции по идентичности. Две ссылки на
один снимок равны; два отдельно созданных снимка, даже с одинаковым содержимым,
не равны. `Найти` у обычного и фиксированного массива использует то же правило.
Разные типы по-прежнему не равны. Фиксированные коллекции могут служить ключами
обычного и фиксированного соответствия, также по идентичности. Нативные опыты
проверяют вставку, чтение, повторную вставку и удаление таких ключей.

`СтрСоединить` / `StrConcat` принимает фиксированный массив непосредственно,
без обязательного обратного копирования. Правила разделителя, преобразования
элементов и отсутствия изменения источника общие с обычным массивом.

Конструкторы фиксированных коллекций не принимают уже фиксированную коллекцию
в качестве исходной: это подтвержденный отказ нативной платформы, а не
временное ограничение. Создание через изменяемый аналог поддерживается.

### Непроверенные границы

Прямые и косвенные циклы по вложенным изменяемым массивам при фиксации пока
дают явную перехватываемую диагностику. Нативное поведение циклов не исследовано.
Повторение одного изменяемого массива в нескольких ветвях при фиксации не
считается циклом: текущая реализация создает отдельный снимок для каждого
вхождения, но сохранение/разделение таких ссылок при прямой фиксации еще не
проверено на 1С. Это отдельный вопрос от уже проверенного обратного копирования.

Порядок обхода структуры/соответствия соответствует текущему порядку вставки
Yadinassi, но не заявляется гарантией 1С. Изменение исходной коллекции во время
обхода фиксированной не меняет ее состав. Точные тексты ошибок, Unicode-правила
имен, обязательность параметров, дополнительные значения конструктора и все
произвольные графы объектов не покрыты текущим нативным набором. Проверенные
вложенные ссылки и выход `Свойство` при отсутствии имени описаны выше; это
не обещание совместимости для всех вариантов аргументов и графов.
Общие ограничения именованных конструкторов, пропущенных аргументов,
динамического `Новый` и глубины рекурсии сохраняются.

### Основания и проверка

Официальный [обзор языка 1С](https://1c-dn.com/1c_enterprise/1c_programming_language/)
описывает неизменяемость фиксированного массива.
[Пример администратора форума 1С](https://1c-dn.com/forum/forum1/ftopic3929/message17487/)
показывает пустую фиксированную структуру и создание из обычной;
[пример ИТС](https://its.1c.ru/db/content/metod8dev/src/developers/dataexchange/esb/i8105993.htm)
показывает конструктор со строкой имен.
[Изменения платформы 8.3.4](https://1c-dn.com/library/v8update_026v8_f_co_new_functionality_and_changes/)
описывают обратные конструкторы и рекурсивное преобразование массивов;
[изменение поведения фиксированной структуры](https://1c-dn.com/library/v8update_026v8_f_co1_changes_that_require_changes_to_the_configuration_and_administrative_settings/)
требует исключения при записи, без воспроизведения старого режима 8.2.16.

Общая [модель типов 1С](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/)
различает сравнение изменяемых и неизменяемых типов, но не разрешает перечисленные
вопросы для конкретных фиксированных коллекций. Равенство, глубина фиксации
и ключи здесь основаны на полученном выводе реальной 1С для `collections.bsl`,
а не на переносе общей классификации типов на эти операции.

Реализация и тесты написаны самостоятельно. Проверки покрывают интерпретатор,
импорты, команду, файл с BOM, stdin, консоль и собранный исполняемый файл,
включая ошибки записи и восстановление после них. Исправление по нативным
результатам сохраняет сценарии, `.out`, `meta.md` и сравниватель без изменений.


## Нативная проверка соответствий, типов и фиксированных коллекций

После добавления `Соответствие`, областей исходного кода, значений `Тип` и
фиксированных коллекций расширен существующий `collections.bsl`. Сохранены
четыре тематических файла; прежние сценарии массива/структуры остаются в начале.
Новые блоки проверяют связные операции, а не полный перебор аргументов:

- Индекс `Соответствие`: раздельные строковые, числовые, булевы и неопределенный
  ключи, замена по равному значению `Тип`, общая ссылка на объектный ключ,
  отсутствие без вставки, удаление/очистка и чтение пар без предположения о порядке.
- Снимки трех коллекций: независимый состав после очистки источников, общая
  вложенная запись, выход `Свойство`, запрет записи и обратные изменяемые копии.
  `Тип`/`ТипЗнч` проверяются сравнением значений, без локализованных названий типов.
- Вложенные массивы: прямая фиксация изменяемого элемента, его фактический тип,
  влияние записи через источник и снимок; отдельно — обратное преобразование
  заранее фиксированного элемента, повторенного дважды, и сохранение общих ссылок.
- Для каждого фиксированного типа одна общая процедура наблюдает равенство
  той же ссылки, отдельно созданного одинакового и другого содержимого,
  `Найти`, конструктор из фиксированного источника и использование как ключа
  обычного/фиксированного соответствия. `СтрСоединить` проверяется на строковых
  элементах непосредственно и после обратного копирования.

Области на двух языках, в том числе вложенные, только организуют этот же
функциональный модуль. Такой синтаксис и отсутствие влияния областей на исполнение
описаны в [официальном уроке 1С](https://1c-dn.com/library/tutorials/practical_developer_guide_marking_custom_module_regions/).
Спорные операции заключены в `Попытка` с постоянными метками `error`/`accepted`;
булевы наблюдения выводятся как `true`/`false`. Отказ одного независимого опыта
не пропускает остальные. Конечная метка `collections.complete: [ok]` означает
завершение сценария, а не совпадение поведения с Yadinassi.

Владелец загрузил полный результат реальной 1С в коммите
[`1c4e20f`](https://github.com/Atridis/yadinassi/commit/1c4e20f9d0c9e735fb6334deb2309b2b2bfbd1a1).
`collections.out` содержит 162 уникальные метки, заканчивается
`collections.complete: [ok]`, маркеров `.err` нет. В том числе независимо
проверены отсутствующий индекс фиксированного соответствия (`error`) и
`Получить` того же ключа (`Неопределено`).

После получения этого результата исправлены наблюдаемые различия: рекурсивная
фиксация вложенных массивов, идентичность при равенстве/поиске/ключах,
`СтрСоединить` фиксированного массива и ошибка отсутствующего фиксированного
индекса. На момент принятия этого изменения все четыре сохраненных нативных сравнения
прошли; сценарии,
эталоны, `meta.md` и сравниватель при исправлении не изменялись.
`basic.bsl`, `functions.bsl` и `strings.bsl` тогда сохранили прежние результаты.
Совпадение этих сценариев не означает полного покрытия языка или всех
пограничных случаев коллекций; непроверенные границы перечислены выше.

Для будущих изменений сценариев сначала нужен новый вывод реальной 1С:
нельзя подменять эталоны результатом интерпретатора или ослаблять сравнение.
Генератор `integrational_tests/test_launcher.py` запускает все тематические модули
и удаляет их прежние результаты перед прогоном; без доступной платформы
для проверки Python-обвязки следует использовать `check_launcher.py`.


## Дробные числа: подтвержденное представление и уточнение нативной точности

Владелец предоставил обновленные `basic.bsl` и `basic.out` с вычислением `10 / 3`
и последовательными удвоениями. Оба файла перенесены без изменения байтов;
`tests/fixtures/basic.out` содержит копию того же результата владельца.
Этот вывод выявил две независимые проблемы: десятичный разделитель и точность
арифметики. После первого `numbers.out` дополнительно подтверждена группировка целой части.
Исправлено представление, а точность арифметики остается открытой до второго
различающего нативного прогона.

### Единое числовое представление

```bsl
Значение = 12.50;
Сообщить(Значение);                   // 12,5
Сообщить(Строка(Значение));           // 12,5
Сообщить("Число: " + Значение);       // Число: 12,5
Сообщить(Число(Строка(Значение)) = Значение); // Да
Сообщить(Number("12.5") = Число("12,5"));   // Да
```

Yadinassi использует единое ограниченное русское представление: десятичная
запятая, без незначащих конечных нулей и с группировкой целой части по три цифры
через неразрывный пробел U+00A0. Например, `Строка(1234.5)` дает `1 234,5`.
Группировка подтверждена первым нативным `numbers.out`. Представление одинаково
для `Строка` / `String`, `Сообщить` / `Message`, конкатенации, строковых функций
и преобразования значения исключения в текст. Выбор русских или английских
имен функций не меняет представление. Числовые значения остаются `Decimal`;
их тип, сравнение и ключи соответствия от разделителя не зависят.

Литералы в BSL по-прежнему используют точку. `Число` / `Number` принимает
каноническую строку с точкой и простое локальное представление с одной запятой:
необязательный знак и цифры ASCII по обе стороны запятой; внешние пробелы допустимы.
Также принимается подтвержденная локальная группировка U+00A0: первая группа
содержит от одной до трех цифр, следующие — ровно по три; дробная часть после
запятой необязательна. Поэтому `Число(Строка(1234.5))` сохраняет исходное значение.
Обычный пробел U+0020 и узкий неразрывный U+202F не подменяют U+00A0.
Смешанные/повторные разделители, неверная длина групп, точка в сгруппированном
числе, экспонента при запятой или группировке и пустая целая/дробная часть
отвергаются. Другие региональные форматы не угадываются. Остальные правила этого
существующего преобразования, включая экспоненциальные строки Yadinassi,
не являются обещанием полной совместимости со всеми форматами ввода 1С.
Прием канонической и локальной формы при обратном преобразовании отдельно
описан в [руководстве, раздел 4.3.9](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/?sphrase_id=1808293).

Системная локаль Python не считывается: результат одинаков на всех платформах.
Полноценная настройка локали, `Формат` и каноническая сериализация еще не
реализованы. Запятая соответствует предоставленному русскому нативному выводу; она не заявляется универсальным разделителем 1С.
Единство явного и неявного преобразования основано на официальных разделах
[использование строковых представлений](https://1c-dn.com/library/using_string_value_presentations/)
и [особенности форматирования значений](https://1c-dn.com/library/formatting_values/).

### Почему точность пока не исправлена

Нативный `basic.out` содержит:

```text
СуммаДробное: 6,666666666666666666666666666
СуммаДробное2: 13,333333333333333333333333332
СуммаДробное3: 26,666666666666666666666666664
```

Во всех трех строках 27 дробных цифр, но общее число цифр растет до 29.
Поэтому глобальная точность Python `Decimal`, равная 28, не воспроизводит
этот результат. Само `10 / 3` в `basic` не выводится: одного этого файла было
недостаточно, чтобы разделить эффект деления, сложения и представления. Первый
`numbers.out` подтвердил значения проверенных частных, но оставил открытыми
правила для других масштабов операндов и точных половин.

Текущая арифметика Yadinassi с контекстом 38 значащих цифр сохранена как есть
и **не совпадает** с этими тремя нативными строками. Правило 38 цифр из
[описания арифметики запросов](https://1c-dn.com/library/bitness_of_results_of_expressions_and_aggregate_functions_in_query_language/)
не используется как доказательство семантики BSL. Разделы 4.3.8–4.3.9
[руководства разработчика](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/)
описывают числа и представления, но не дают достаточного алгоритма точности деления.

### Компактный нативный сценарий numbers.bsl

Тематический `numbers.bsl` первоначально добавлен без заранее созданного `.out`.
Затем владелец предоставил настоящий результат на PR-ветке в коммите
`f61b7ac783c6bc0f77a44afde604a1ebfd621ecc`; его 32 строки и исходные эталоны
сохранены без изменений. Первый опыт проверяет:

- Прямые результаты `1 / 3`, `10 / 3`, `100 / 3` и числовые сравнения
  с 27 дробными и 28 значащими цифрами; масштабированный остаток и его
  числовое сравнение с кандидатом для 38 значащих цифр.
- `2 / 3`, `±1 / 7`, дробный операнд, маленький и большой порядок результата.
  Ошибки двух крайних порядков помечаются `error`, не прерывая остальной опыт.
- Первые два удвоения `10 / 3`, их сравнение с уже полученным `basic.out`,
  обратное умножение на 3.
- Конечная точная дробь, прибавление нуля и деление на единицу.
- `Строка`, конкатенация и прямое `Сообщить` для `1234.5`, чтобы увидеть
  возможную группировку разрядов в текущей локали.

Метки булевых наблюдений используют `true` / `false`; первый опыт заканчивается
меткой `numbers.complete: [ok]`. Нативные числовые сравнения подтвердили 27
дробных цифр у проверенных целых делений; масштабированный остаток равен -3.
Однако `13.1 / 3` дает 36 дробных цифр, `0.0000000000000000000000000001 / 3` —
63, а большое частное содержит 54 цифры всего. Глобальный контекст 28/38 цифр
и единая шкала 27 не объясняют этот набор. Рост кратно девяти — наблюдение,
а не доказанное универсальное правило. Все знаменатели первого опыта целые:
пока нельзя отделить влияние числителя от знаменателя, исходных конечных нулей
и промежуточных результатов.

В этот же файл добавлен компактный второй блок из 16 делений: дробные
знаменатели, одинаковые и разные масштабы операндов, границы 9/10 и 18/19
дробных позиций, конечные нули, повторное деление на 7, отрицательные дроби
и точные половины `±1 / 2000000000000000000000000000` и
`3 / 2000000000000000000000000000`. Каждая операция имеет
свою метку и изолирует ошибку. Новая последняя метка —
`numbers.precision_v2.complete: [ok]`; полный вывод содержит 49 строк.

**Сохраненный `numbers.out` относится к первому блоку.** После расширения
сценария он намеренно не дописывался результатом Yadinassi: нужен новый вывод
реальной 1С со второй завершающей меткой. Сравниватель по-прежнему обнаруживает
расхождение `numbers` и настоящую разницу точности `basic`; проверки не пропущены
и не ослаблены. `collections`, `functions` и `strings` сохраняют прежние эталоны;
`meta.md` и сравниватель не менялись. Полный прогон пока не зеленый.
`Цел` / `Int` и `Окр` / `Round` в эту итерацию не входят: сначала требуется
подтвердить базовую арифметику по дополнительному выводу владельца.
