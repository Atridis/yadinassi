# Временное хранилище source-приложения

Source-host предоставляет `PutToTempStorage`, `GetFromTempStorage`,
`DeleteFromTempStorage`, `IsTempStorageURL` и русские варианты серверным
модулям своего живого приложения. Клиент того же SourceApplication может
вызвать `PutToTempStorage(Значение, UUID)` и `GetFromTempStorage(Адрес)`
через логический сервер этого приложения. Обе стороны используют одно
хранилище; клиентский кэш не создаётся. Это оперативная память приложения, а
не доступ к базе, файловая служба или общий процессный кэш.

Используется существующий bounded store strict-приложения, но с отдельной
проверкой source owner/family/scheduler. Авторизация и количество аргументов
проверяются до вычисления аргументов именованного вызова. Наличие адреса не
даёт чужому или закрытому интерпретатору доступа. Закрытие, отмена и
неудачный старт освобождают все значения.

Новая запись требует явно переданный UUID. Замена по существующему адресу,
удаление и проверка адреса пока доступны только серверу. UUID здесь не
означает реализованный жизненный цикл формы. Неявные, числовые и пустые
строковые владельцы остаются неподдержанными.
Удалённый адрес распознаётся, чтение возвращает Undefined, повторное удаление
безвредно; заново записать значение по удалённому адресу нельзя.

В одном серверном контексте коллекции сохраняют identity и видимые изменения
через alias. Snapshot служит только проверкой формы и учётом размера, а не
подменяет значение копией. Обычный ServerCall по-прежнему копирует вход/выход
согласно своему закрытому контракту. Клиентские Put/Get также копируют
передаваемые значения (допущенные скаляры, ациклические массивы и структуры)
и не передают изменяемые alias через границу. Это не новый нативный замер.
Ссылки на БД и объекты с полномочиями не передаются. Раздельные процессы
клиента и сервера в этот вариант не входят.

Сохраняются локальные бюджеты: 128 записей, 32 MiB расчётного удерживаемого
объёма, 100000 узлов. Put и успешный Get проверяют также изменения через ранее
выданные alias. Неудачная запись не заменяет прежнюю. Это operation-time quota,
не перехват каждого изменения коллекции; Delete и закрытие доступны для очистки.
Серверные операции остаются in-memory и допустимы внутри source SafeMode.
Клиентский переход сохраняет ограничения ServerCall для SafeMode и активной
транзакции.

Проверки повторяют 13 допущенных наблюдений из существующего нативного прогона
`43056863128`; три остальных формы owner явно проверяются как локальные
ограничения. Это не новый нативный прогон source-host и не заявление полной
совместимости с временным хранилищем платформы.
