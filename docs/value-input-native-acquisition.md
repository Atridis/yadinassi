# Owned scalar input and ValueList native acquisition

This separate lane measures eight real native interactions. It does not install
input support into an ordinary application and does not declare keyboard/pixel
parity. No native observation has been collected merely by adding this packet.

1. String initial `seed`, select all, type ASCII `edited`, confirm.
2. Number initial `12.5`, confirm unchanged.
3. Date initial `2024-02-03 04:05:06`, confirm unchanged.
4. Boolean initial `True`, confirm with the initial native focus.
5. Scalar input, cancel using Escape.
6. Two-item ValueList, preselect second item, confirm. Record result identity
   against the retained original second item and its value independently.
7. ValueList, cancel using Escape.
8. String input, select all, delete to empty, confirm.

Every flow records callback count, the mutation of the same AdditionalParameters
Structure, native result type, value match, list identity and observed event order.
Both returned-before-callback and callback-before-returned are admitted as
observations. Different observed values are evidence, not rewritten expected data.
Callbacks are only supplied to the native APIs, never invoked by the driver.

The controller runs only on the probe's authenticated private `:99` display.
It loads already available X11/XTest libraries, with no installation or fallback
commands. An exact nonce-bearing title must identify one window. The window PID
must be in the newly owned process session/group, with the expected executable;
the leader start identity is rechecked. Focus must be within that dialog. Each
bounded chord is queued while holding that private X server, with release in a
finally clause; there is no polling or sleep inside the grab. Unknown title,
missing PID, unsupported focus or library absence refuses acquisition. Boolean
navigation is not guessed if its native window cannot satisfy those conditions.

Caps: eight windows acted on, at most 512 enumerated windows and depth eight per
poll, 2,400 polls, 48 key presses, 120 seconds for enterprise execution. Cleanup
kills only the newly owned process group on failure, then uses the existing
private bus/process census. This driver never touches a user's desktop or network.

Authored packet hashes, transformed executable BSL and EPF are rechecked before
and after execution. Designer acceptance is enough for XML layout loading;
redumped XML byte/structural parity is not required. Historical acquisition runner
files are not modified or reused for this new lane. The dedicated source-bound
controller is included in staged and reported trusted inputs.

The stage publishes only fixed counts/booleans and bounded typed result codes.
It exports no window text, PID, display credentials or arbitrary process output.
Native success still requires review of the recorded semantics before a runtime
claim. No workflow or native execution is enabled by this document alone.


## Failed acquisition diagnostics

The first eight-flow attempt reached Enterprise after Designer build and exact
executable BSL redump verification, but exported no observations. Its closed
report stated `enterprise/unexpected_failure`, with no valid entered/completed
markers. That evidence does not identify the original controller exception and
does not establish native input semantics. Module-level `Items` and unqualified
`Title` were removed as managed-form context collisions: the packet now retains
`ProbeItems` and explicitly declares a local `ProbeTitle`.

Controller failures now export only a closed phase, fixed reason code and the
number of completed owned actions (0–8). Unknown exceptions become
`unexpected_exception`; operating-system errors become `os_error`, without their
messages. The host validates the exact diagnostic shape before retaining it in a
failed report. No window titles, process identifiers, file paths, arbitrary logs,
credentials or input text are exported. These diagnostics do not relax the
existing PID/session/start-time, display, focus, source or cleanup guards and do
not turn an unsuccessful acquisition into observations.
