# Инкрементальное хеширование данных

`DataHashing` / `ХешированиеДанных` и `HashFunction` / `ХешФункция`
добавляют полный обычный путь от текста, двоичных данных, потока или локального
файла к контрольной сумме. Реализованы CRC32, MD5, SHA1, SHA256 и SHA512.
Это API совместимости/контрольных сумм, **не протокол аутентификации,
не хранение паролей и не рекомендация MD5/SHA1 для защиты данных**.

```bsl
Хеш = Новый ХешированиеДанных(ХешФункция.SHA256);
Хеш.Добавить("часть 1"); // UTF-8, без BOM
Хеш.Добавить(ПолучитьДвоичныеДанныеИзСтроки("часть 2"));
Снимок = Хеш.ХешСумма; // ДвоичныеДанные, чтение не сбрасывает накопление
Хеш.Добавить("часть 3");
```

## Обычный API

- Обязательный параметр конструктора — точное значение `HashFunction`.
- `Append` / `Добавить`: String (UTF-8), BinaryData либо точный поддержанный
  Stream/MemoryStream/FileStream. Только для потока есть необязательный Count;
  пропуск читает остаток. Поток заимствуется, не закрывается.
- `AppendFile` / `ДобавитьФайл`: только явно указанный локальный обычный файл,
  открытый на чтение; внутренний дескриптор закрывается также при ошибке.
- `HashFunction` / `ХешФункция` и `HashSum` / `ХешСумма` только для чтения.
  CRC32 возвращает Number, остальные алгоритмы — новый BinaryData со снимком.
- RU/EN имена типов, `TypeOf`, динамический `New` и известные необязательные
  аргументы включены. Неподтверждённый внутренний codec явно отклоняется.

## Ресурсы и границы

На одно добавление допускается не более 16 MiB, на объект — 64 MiB накопленных
данных. Это ограничения реализации, не заявленные лимиты 1С. UTF-8 размер
проверяется перед выделением выходных байтов; поток проверяется перед чтением.
Состояние хеша обновляется через копию и публикуется только после успешного
чтения/вычисления. При неуспехе возвращается прежний логический курсор потока;
внешнее изменение самого файла этим не отменяется и не блокируется.
Пользовательские Python-потоки/подклассы, callbacks, URL, UNC, устройства и ADS
не допускаются; действуют существующие FileStream-границы без новых полномочий.

Ошибки provider не вызывают fallback на другой алгоритм или изменение настроек ОС.

## Источник и статус

Официальный EDT `platform-doc.jar` SHA-256
`a8cf9c3cd5d7828958dcf69d8864cf6664180260e4d50cbff338921304c7e642`:
`SyntaxHelperContext/objects/catalog63/DataHashing` и
`objects/catalog2/catalog2088/HashFunction`. Базовый API с 8.3.1;
SHA1/SHA256 с 8.3.3, SHA512 с 8.3.18. Документирован server/thick client/external
connection; thin/web поддержка не заявляется. Существующий native runner
использует managed-thick-file, не новый режим исполнения.

Первичная real-1C калибровка **ещё не получена**. CRC32 signedness,
Count/EOF, UTF-8, снимки, положения и lifetime проверяются одним ограниченным
[40-сценарным пакетом](data-hashing-family-measurement.md). Локальные тесты
и стандартные checksum-векторы не заменяют доказательство native parity.
