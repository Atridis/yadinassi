# Read-only document tabular sections

This block extends bounded document cards to an end-to-end document → Items →
Product reference workflow: `Count`, zero-based `Get`/indexing, `For Each`,
`LineNumber`, fixed-reference `Find`, `IndexOf`, and numeric `Total`.
Section and row `TypeOf`/`Type` identities are scoped to the same complete
CONFIG metadata snapshot. Repeated retrieval preserves immutable identity within
one unchanged logical section; rows of different document owners are distinct.

Native measurement 41263661105, source e52b90d6502e0882c59f6e32709d8b69e9a0cb02,
contains two independent metadata identities, opposite column orders, initial
and controlled rewritten fixtures, both client/server contexts. All 32 native
blocks are available. Its raw selected CONFIG/DBNames/three-table bytes and
native programs replay through the public interpreter using synthetic transport.
This replay is not a saved native database or final actual `.1CD` parity claim;
that final source-composed gate remains pending.

## Closed storage profile

- Existing measured document String8 nonperiodical header and five mixed header
  attributes; zero or one tabular section.
- Five columns: one fixed Catalog reference, three Number(9,2) values, one
  variable String32; forward/reverse measured type order. Names and metadata,
  generated type and physical field IDs are derived from CONFIG/DBNames, not
  fixture literals or XML input.
- Full CONFIG catalog/document membership and target type mapping are retained.
  DBNames section UUID must have exactly the measured VT and LineNo roles;
  physical aliases, unknown roles and ambiguous candidates fail closed.
- One CONFIG → PARAMS → Document → section graph shares read/ownership budgets.
  Section records cannot open before their identical owner-document binding.
- Owner raw16 is decoded as a document reference and must join a live selected
  document. Key raw4 is opaque, not a UUID or sort key. LineNumber must be
  positive, unique and contiguous per owner. Sorting uses LineNumber, not
  physical slots: rewriting actually changes the physical/logical ordering.
- All-active section slots only, at most 4096 slots/rows within existing limits.
  Empty structural cases are admitted without claiming an additional native
  empty-table capture. No free chain is inferred from Catalog behavior.

`Find(value,"Product")` supports explicit single fixed-reference columns only;
missing returns Undefined and the first matching logical row is returned.
`IndexOf` returns -1 for a row from another owner. Numeric `Total` handles empty
sections as zero with bounded exact Decimal arithmetic. Empty/absent document
references expose empty sections, as measured.

Public interpreter mutation, object acquisition, posting, query execution,
section Add/Clear/Sort/Unload and writable rows remain unavailable. Dynamic
section/row types are refused explicitly by codec, TypeDescription and dynamic
construction consumers. Composite columns, other qualifier/layout profiles,
multiple sections, deletion/free chains and unmeasured presentation are `!todo`
boundaries, not silent fallbacks.

## Public fixture minimization

`document_items_native.json` is constructed with only source/report hashes,
selected five CONFIG files, selected three-table bytes/declarations and DBNames,
source-bound programs and native observations. Installations, sessions, audit
material and authentication tokens are excluded. Exact retained subsets are
checked against the private original report; recursive auth-field rejection and
byte hashes protect the public fixture. The original full report stays private.
