# Прямой движок: границы regex и JSON

Исправление Python 3.10 regex CI не использует legacy fallback и не меняет
regex-алгоритм, исходный witness, ожидаемые байты результата или лимиты ресурсов.

- Пропуски необязательных аргументов разрешены только для текущей canonical
  реализации четырёх regex-функций, включая зарегистрированные aliases.
  Число аргументов и обязательные позиции проверяются до вычисления аргументов.
  Используется существующий sentinel `strings._OMITTED`, не `None`.
- Подмена стандартного имени не разрешает пропуски. Изменение реализации уже
  связанного HostFunction во время вычисления аргументов отвергается до вызова,
  чтобы sentinel не попал произвольному обработчику. Смена записи registry не
  перепривязывает уже связанный вызов, а следующий вызов видит новую запись.
- Конструкторы JSONReader, JSONWriter, JSONWriterSettings подключены через
  конечный список и требуют canonical registration. JSONLineBreak и
  JSONValueType используют существующие системные пространства имён.
  Доступ остаётся через публичные get_member/get_method, без Python reflection.
  Существующие файловые проверки, ограничения ресурсов и ограничения
  поддерживаемых параметров JSON не отменяются.
- Regex result/group остаются неконструируемыми. Попытка New теперь выдаёт
  перехватываемую runtime-ошибку, а не отклоняет весь модуль при компиляции.
- Те же границы подключены к клиентскому, серверному, NoContext и dual планам.
  Это не общее разрешение пропусков у других функций, методов и конструкторов.

Generated-client regression сравнивает полный BSL-вывод с теми же expected
bytes. Он больше не зависит от legacy-физического представления массива
`.items`: прямой движок хранит его как list.

Проверки включают live/prepared registration, отсутствие effects при раннем
отказе, смену реализации callback, закрытие owner, серверные планы и освобождение
bound callable без cyclic GC. Реальная 1С этим локальным прогоном не проверяется.
