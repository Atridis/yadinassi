# Coverage map before CI cost reductions

This is a proposed next-iteration map for audit C1–C3, not an implemented
reduction or a claim of measured speedup. The present change removes no test,
BSL observation, frozen scenario, native gate, fixture boundary or platform gate.
Ordinary PR/main macOS ARM remains explicitly paused; every tag/manual run retains
ARM and release still requires full four-platform coverage.

## C1: separate binary transport from repeated semantics

| Existing source | Coverage that must survive | Proposed replacement boundary |
| --- | --- | --- |
| `scripts/smoke_test.py` family `check_*` helpers | Every existing family assertion, error expectation, native literal and output ordering | First inventory every asserted observation and map it to an independent semantic test; only then consolidate frozen launches by family. An assertion without a mapped owner stays in frozen smoke. |
| `check_tree_findrows`, `check_text_document`, other helpers repeating command/file/stdin/console routes | CLI `-c`, Cyrillic `-с`, `--command`, UTF-8/BOM file input, stdin, redirected console and exit handling | Small independent transport matrix plus one frozen scenario per family. Do not assume interpreter-only unit tests cover packaged transports. |
| `main()` import/error scenarios and sanitized subprocess environment | Bundled resources/dependencies, operation outside the source tree, non-ASCII paths, relative/nested imports, canonical diagnostics, failure exit/stderr | Keep standalone packaged checks. Continue excluding source-tree/Python environment leakage. |
| `check_saved_native_outputs`, timezone and UI frozen smoke | Independent expected bytes, packaged timezone data, actual bundled UI resources and lifecycle | Keep dedicated frozen checks and source binding; do not replace evidence with outputs generated by the implementation under test. |
| Interactive/stateful cases | State retention, repeated input, recovery, cleanup and process termination | Preserve complete interaction sequences; a concatenated one-shot program is not an equivalent substitute. |

Before removing a launch, record its old command, family assertions, new owner,
fixture/transport dependencies and negative-path coverage. Compare expected bytes
and launch counts without rewriting native observations. Run the final frozen
checks on all supported platform routes before accepting a speedup claim.

Comparing two executions of the same current engine is not an independent
historical oracle. Do not generate replacement fixtures from current output and
call them captured native evidence. The first two tests remain unchanged until
that oracle and prefix mapping exist.

## C3: exhaustive packet checks versus repeated preparation

Both `test_native_preprocessor_budget.py` and
`test_native_preprocessor_runtime_budget.py` currently rebuild provenance through
`report_for()` and run filesystem/CLI summary projection inside large enumerations.

- Keep every enumerated success subset, client-failure frontier, early/server
  frontier, async/exceptional majorant, codec roundtrip and schema/mode rejection.
- Candidate preparation reuse is per test only: build unchanged source provenance
  once, retain an immutable template and deep-copy mutable report dictionaries.
  Do not cache across tests or production calls, and do not skip hashing in tests
  whose purpose is source mutation/provenance rejection.
- Keep full production CLI/filesystem checks for accepted output, maximum envelope,
  not-started/failed stages, schema downgrade, invalid provenance/artifact,
  unexpected host failure and accepted-native/comparison-mismatch distinctions.
- Preserve independent source substitution, all-output invalidation, readiness
  revocation, private marker, cleanup, partial-result and size-cap regressions.
- Only move repeated CLI projection out of exhaustive loops after a table maps
  each removed invocation to a retained shape, status and limit check. Every
  codec/validator/size enumeration still runs; production limits stay unchanged.

A later patch should include exact before/after counts and deterministic call
instrumentation proving preparation reuse. CI wall-time measurements follow;
the audit's historical timings alone do not establish the improvement.
