# Формы складской конфигурации с перечислениями

`inventory-enum-forms-v1` — отдельное разрешение на полный исходник конфигурации
для физического формата 16. База `inventory-enum-v1` сама по себе не получает
формы, команды или отчёты. Импорт проверяет исходные XML/BSL, явный manifest,
перечисления и формы; сохраняет исходные байты и проверяет их при открытии.

UI уже подготовленной базы открывается через `yadinassi --ui --f PATH`.
Отдельный внутренний маршрут `--inventory-enum-application` не заменяет импорт
и не активирует другую базу автоматически.

## Проверяемый пример

Полный authored XML/BSL исходник находится в
`examples/configuration-inventory-enum-application`. В отличие от core-примера,
здесь есть формы, явные команды, видимые Unit/State и manifest UI.

```sh
yadinassi --create-db db/enum-ui.sqlite --import-xml examples/configuration-inventory-enum-application --source-profile inventory-enum-forms-v1
yadinassi --ui --f db/enum-ui.sqlite --open-browser
```

Создайте товар и склад, выберите единицу товара; в поступлении выберите склад,
состояние и единицу строки. Запишите и проведите документ, проверьте движения,
повторно откройте его и отмените проведение. Пример не содержит готовой базы
или пользовательских данных. Пустой список сначала ожидаем.

## Поддержанный host-сценарий

- Объектные формы справочников и документов с типизированными полями
  перечислений, включая строки табличных частей.
- Выбор и очистка значения через ограниченный серверный список. Браузер
  получает временные непрозрачные идентификаторы, не UUID хранения.
- Изменение формы остаётся черновиком до записи; запись, обновление списка
  и повторное открытие используют тот же проверенный исходник.
- Список записей показывает код, наименование и пометку удаления. Это
  проекция списка, а не универсальный сериализатор всех типов реквизитов.
- Read-only отчёты сохраняют внутреннюю типизацию перечислений при расчёте,
  но выводят названия значений как текст, без capability/UUID.

Идентичность перечисления принадлежит живому экземпляру интерпретатора и
проверенной базе. Значения чужой базы, поддельные значения и закрытые
экземпляры не принимаются. Вызов из браузера не получает право проведения:
проведение остаётся отдельной разрешённой операцией host-контроллера.

## Граница подтверждения

Это реализация host UI, а не утверждение полной совместимости форм 1С.
В отдельном native acquisition загрузка и проверка существенной схемы,
модулей и событий прошли, но восемь наблюдений форм не завершились:
ENTERPRISE вошёл в сценарий и достиг timeout. Старые или отсутствующие
результаты не считаются подтверждением новой реализации. Косметическое
равенство XML после Designer-выгрузки не требуется.
