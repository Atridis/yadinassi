# Единый профиль компиляции загруженного источника

При явном запуске XML-источника можно выбрать существующий профиль
`--preprocessor-profile managed-thick-file`. По умолчанию остаётся `standalone`.
Выбор сохраняется на всё время жизни приложения, включая ленивую компиляцию:

- модуля приложения и сеансового обработчика;
- общих модулей на каждой разрешённой стороне и поиска глобальных экспортов;
- модулей менеджеров;
- явно выбранной поддерживаемой формы, её клиентских/серверных обработчиков
  и вызванных из них общих модулей.

Это **выбор ветвей исходного текста**, не запуск настоящего толстого клиента
1С, не права доступа и не новый транспорт. Профиль не выбирается автоматически
по наличию SQLite, XML-метаданным или операционной системе.

В `managed-thick-file` символы `Client`, `Server` и
`ThickClientManagedApplication` истинны; их русские имена эквивалентны.
Логические `AtClient`/`AtServer` сохраняют существующую контекстную политику.
Например, обе ветви `#If Client` и `#If Server` могут содержать объявления
общего модуля, но их наличие **не разрешает** клиенту вызов серверного менеджера.
Метаданные по-прежнему определяют сторону общего модуля. Привилегированные
модули, файловые импорты конфигурации и неподдержанные сервисы отклоняются.
Мобильные флаги остаются ложными, неизвестные символы дают ошибку.

Профиль компилируемой формы хранится вместе с её доверенным AST; его нельзя
исполнить через `admitted_program` с другим явно указанным профилем.
Форма не приобретает поддержку новых элементов, хранения или NoContext-вызовов
только от смены профиля. Общий `InvocationServer` пока принимает только
standalone-программы: иной sealed-профиль отклоняется до исполнения. `CurrentRunMode()` не превращается в выдуманное значение
нативного режима: источник работает в собственном host Yadinassi.

## Границы проверки

Тесты проверяют согласованность компиляции и исполнения Yadinassi, изоляцию двух
одновременно открытых приложений с разными профилями, сеанс/общие/глобальные/
менеджерные модули, создание и команду формы, сохранение ограничений полномочий.
Нативные наблюдения для старого скалярного профиля не доказывают полную
совместимость всех видов модулей и форм. Отдельный acquisition-пакет профилей
компиляции остаётся источником будущей калибровки, а не автоматически зачтённым
результатом этих изменений.
