# Экспорты модуля управляемого приложения

Source-runtime предоставляет экспортные функции, процедуры и переменные
управляемого приложения неглобальным клиентским общим модулям и клиентскому
коду выбранной поддержанной формы. Серверный код и глобальные общие модули
не получают клиентский контекст приложения.

Переменные представлены общими ячейками приложения, а не снимками значений:
чтение, присваивание, изменение коллекции, передача по ссылке, Eval и Execute
наблюдают одно состояние. Локальные параметры и явные переменные, собственный
контекст формы и собственные процедуры сохраняют приоритет. Встроенный и
глобальный контекст разрешается прежде экспортных процедур приложения.
Приватные объявления приложения не экспортируются. Вызов экспортной процедуры
сохраняет и восстанавливает активные локальные переменные вызываемых процедур.

Ссылка на общую переменную создаётся только в разрешённом клиентском контексте.
Её внутренний доступ проверяет семейство и время жизни приложения. Во время
штатного ServerCall такая ссылка остаётся у интерпретатора клиента; сервер
получает копию значения, а после успешной валидации пакета движок возвращает
значение в исходную ячейку. Это не открывает серверу переменные приложения.
Закрытие приложения делает сохранённые внутренние ссылки недействительными.

Контракт основан на [описании типов модулей в руководстве 1С](https://1c-dn.com/download-trial/files/guides/developer_guide.pdf)
и [описании контекста формы](https://kb.1ci.com/1C_Enterprise_Platform/Tutorials/Practical_developer_guide_8.3/Lesson_5._Theory/Modules/Form_module_context/).
Локальные тесты проверяют реализацию Yadinassi, не новое измерение на реальной
1С. Командные модули, произвольные формы и другие ещё не активированные виды
модулей не объявляются поддержанными благодаря этому механизму.
