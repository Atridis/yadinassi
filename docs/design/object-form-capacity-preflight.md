# Saved document form capacity preflight

Opening a saved document with more than the existing 32 rows per table or 256
aggregate cells is now a known refusal before the host allocates a per-form
identity, live form interpreter, root operation service or journal. Canonical
source admission may still compile and validate templates with temporary validation-only
interpreters; that does not execute form lifecycle or create a live editor. The user keeps the
existing application, other forms and reports. No rows are truncated, no data is
saved and no table/transport limit is increased.

The broker validates the fresh context's exact source and profile, then uses an
admitted read lease to capture the immutable document card and expected revision.
The same card is handed to the exact ordinary, posting13 or inventory15 editor;
there is no second record read between preflight and installation. Normal source,
schema and owner checks remain, and the original revision is still the optimistic
write guard if another actor changes the document after the read.

Only row/cell capacity is classified here. Missing/corrupt records, changed grants,
cleanup failures and unknown creation/transport outcomes remain fail-closed.
Text-byte, encoded-envelope and source lifecycle failures have not acquired a new
safe-refusal guarantee. Large-table editing needs its own bounded paging/editing
contract; report pages are not editable document pages.

This is independent of the current UI aggregate and stock statement feature.
There is no migration, expanded profile or change to root transaction admission.
