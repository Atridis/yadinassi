# Лёгкая основа СпискаЗначений

Хранение: обычный список элементов. Элемент — список из четырёх фиксированных
полей: `[значение, представление, пометка, картинка]`. У элемента отдельно хранится один slot `_id`, у списка — счётчик `_next_id`.
Отдельного `__dict__` у каждого элемента нет. Сгенерированный Python обращается по индексам полей.
Нет owner/weakref, счётчика изменений, кеша представления, описания типов или
словаря идентификаторов в пути добавления/чтения. Старый предел 100000 элементов
проверяется только на росте Add/Insert/Load, не при чтении.

Это намеренно неполная совместимость с 1С. Индексы Get используют Python-поведение
(отрицательные индексы, Decimal приводится к int), сортировка использует Python,
направление сортировки — bool; ограничения типа значений и UI не реализованы.
Идентификатор выдаётся монотонно, FindByID делает простой линейный поиск.
После удаления сохранённый элемент сохраняет ID (явное отличие от старого пути). Сохранённые ссылки на элементы
остаются ссылками на тот же объект при вставке/удалении соседей и сортировке.
Копия списка создаёт новые элементы, но сохраняет ссылки на значения полей.

## Отложено: индекс идентификаторов

Предложение владельца: отдельный `id → индекс` для поиска, синхронизируемый при
изменениях. Добавление в конец даёт ожидаемо O(1) обслуживание; вставка/удаление
в середине с сохранением порядка требует обновления смещённых индексов O(N).
Сортировка требует перестроения индекса O(N), помимо самой сортировки.

Альтернатива: `id → элемент`. Поиск элемента ожидаемо O(1), а перестановка строк
не меняет словарь. Но получение текущего порядкового индекса по элементу остаётся
O(N), если не хранить дополнительный обратный индекс. Удаление требует удаления
записи; сохранённые внешние ссылки и повторное использование ID требуют отдельно
зафиксированной семантики.

Сейчас реализован только линейный поиск по `_id`; ни один словарный индекс не реализован. Выбор следует сделать отдельным изменением
по реальным операциям поиска и замерам цены поддержки, не возвращая этот учёт в
каждое чтение четырёх полей.
