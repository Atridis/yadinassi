## Observed behavior

Both zero-argument constructor aliases and both type-name lookups work.
`String(TypeOf(document))` is `Текстовый документ`; the independently observed
object display is `ТекстовыйДокумент`. The spaced display is not a lookup alias.
An empty document has zero lines and an empty text.

`SetText` / `УстановитьТекст` preserves the exact CR, LF or CRLF separators.
`GetText` / `ПолучитьТекст` returns that raw text. `LineCount` /
`КоличествоСтрок` and one-based `GetLine` / `ПолучитьСтроку` recognize these
three separators; a terminal separator does not add another empty line.
Two CRLF separators alone give two empty lines. The observed Cyrillic/astral/
combining sequence and U+2028 are preserved; U+2028 is not a line separator.
GetLine at zero, beyond the last line, or one in an empty document returned `""`.

The mutation witnesses establish:

- `AddLine` / `ДобавитьСтроку` appends LF-terminated text, first inserting LF
  when the existing last line has no terminator. An existing terminal CRLF is
  retained. A blank addition creates one empty LF-terminated line.
- `InsertLine` / `ВставитьСтроку` inserts before a one-based line. Zero prepends;
  `Count()+1` and `Count()+2` append without filling a gap.
- `ReplaceLine` / `ЗаменитьСтроку` replaces the selected span, including its
  old terminator, with LF-terminated text. Zero replaced the entire two-line
  document; `Count()+1` left it unchanged.
- `DeleteLine` / `УдалитьСтроку` removes the selected span and its terminator.
  Zero cleared the two-line document; `Count()+1` left it unchanged.
- `Clear` / `Очистить` clears populated and empty documents.

Untouched spans preserve their original separators. AddLine and ReplaceLine also
have an internal-LF argument witness. These were statement calls: the captured
`R=U` is the harness's initialized answer sentinel, **not evidence of a mutator's
expression return value**. Yadinassi exposes these mutators as procedures.

## Bounded model and deliberate generalizations

The implementation applies a generic span-editing algorithm to other text and
nonnegative integral indices within its limits; it does not look up captured
A/B/X/Y constants. Zero/past behavior on other document shapes, repeated edits,
more lines, insertion of multiline values and larger positive indices are
**algorithmic extensions of the finite observations**, not additional native
measurements or a universal platform claim.

Only exact String arguments and finite, integral, nonnegative Number indices are
accepted. Negative/fractional/non-number indices and implicit conversions remain
outside this slice. SetText supports scalar Unicode and arbitrary CR/LF/CRLF
combinations. Line-mutator arguments support empty text or scalar Unicode with
internal LF but no CR and no terminal LF; other delimiter forms have not been
measured for these arguments and are deliberately rejected. Lone surrogate units
are also rejected. These are local subset boundaries, not native error claims.
An edit that would newly combine an untouched lone CR with an inserted or
newly adjacent LF is likewise rejected before mutation: the 44 probes do not
establish whether native line boundaries collapse at that splice. Existing CRLF
separators remain supported. Empty-line Add/Insert/Replace after a lone CR and
Delete that exposes such a seam therefore stay outside this slice.

Local budgets are 1,000,000 UTF-16 text units and 100,000 lines. Mutations validate
input, prospective size and line count before committing state. Huge positive
Decimal indices are bounded by comparison before conversion to Python integers.
The limits and rejection atomicity are Yadinassi policies, not observed 1C maxima.
All listed arguments are required; optional omitted forms are not added.

## Closed boundaries and validation

No filesystem Read/Write, streams, UI, encoding properties, async API, indexer,
iteration or host reflection is exposed. Internal/XML codecs (including Type
records), TypeDescription/typed cells, ValueIsFilled and cross-context transport
remain unsupported. Ordinary same-side references use the existing object model;
this is not evidence for native transport or object identity contracts.

The integration source, its adapters, historical source-only inverses, historical
fixtures, transport caps and workflows remain byte-identical to the measurement
revision. The runtime provenance inventory grows **62 → 63** because of the new
`yadinassi/text_documents.py`; its hash changes and must be rechecked in fresh CI.
The current finite transport proof leaves only 7 bytes of worst-case async wire
headroom (8185 of 8192) and 237 bytes of public-summary headroom (32531 of 32768).
Oversize payloads still fail closed. Further runtime modules require a separate
budget/design review, not an increase to these caps.
The bounded packaged smoke exercises the API through command aliases, BOM file,
stdin and console without calling any file method. Native-witness unit tests,
local boundary/budget tests and whole-source replay remain distinct checks.
