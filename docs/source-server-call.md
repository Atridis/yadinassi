# Серверные вызовы общих модулей источника

Source-runtime допускает вызов экспортной процедуры или функции общего модуля
из клиентского кода, если XML задаёт `Server=true`, `ServerCall=true`,
`ClientManagedApplication=false` и `Global=false`. Модуль компилируется на
серверной стороне с явно выбранным профилем приложения. Если модуль доступен
и клиенту, вызов остаётся клиентским, а флаг ServerCall не принуждает перенос.

Это логическая граница внутри Yadinassi, не сетевой сервер 1С. Используется
существующий механизм вызовов интерпретатора: проверка экспортности, перенос
поддержанных значений, изолированная серверная активация, возврат результата и
copy-back параметров. `Val` не изменяет исходную коллекцию клиента; для
параметров по ссылке поддерживаются переменные, а неподдержанные выражения
отклоняются до выполнения тела. При исключении либо непереносимом результате
изменения параметров не возвращаются клиенту.

В серверной активации сохраняются приложение, Metadata, поддержанные сервисы
источника, профиль компиляции и возможность вызывать другие серверные или
глобальные модули. Внутреннему серверному модулю не нужен ServerCall для вызова
с сервера, но кеширование такого модуля не открывает доступ клиенту.

## Границы

- Безопасный режим и транзакционные ограничения переноса не обходятся.
- Привилегированные модули не получают полномочий и по-прежнему отклоняются.
- Чужое или закрытое приложение не может использовать кеш получателей.
- Клиентские модули не становятся доступны серверу.
- Межсторонние модули с `ReturnValuesReuse` пока отклоняются явно: контракт
  кеширования через границу не реализован. Обычные односторонние правила не меняются.
- Поддержка новой категории вызовов не означает поддержку всех объектов,
  типов параметров, форм или полной конфигурации.

Focused-тесты проверяют локальный контракт Yadinassi, а не новую нативную
калибровку 1С. Результаты прежних нативных сценариев не считаются доказательством
полной совместимости source-модулей.
