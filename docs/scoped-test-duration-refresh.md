# Обновление истории времени тестов

`python -m scripts.refresh_test_durations --reports DIRECTORY --source SOURCE_SHA --run RUN_ID --output scripts/test_durations.json --scope required-platforms`

По умолчанию сохраняется строгий режим `full-four`. Явный режим `required-platforms` принимает только полный успешный heavy-premerge набор платформ, предусмотренных политикой данного события. Он вызывает неизменённый `coverage(binding, reports, True)`; отсутствующие, лишние, смешанные или неуспешные разделы не допускаются. Это не утверждение о покрытии исключённой mac-arm.

CLI всегда создаёт sidecar `OUTPUT.audit.json` с точным binding, областью покрытия, SHA256 отчётов и выходного файла. В репозитории sidecar хранится как `scripts/test_durations.audit.json`. Сама история остаётся schema 1; интерфейс partitioner не меняется.

Времена отражают отдельные исполнения тестов, а не setup/teardown модульных и классовых fixtures. Этот недостающий overhead не распределяется искусственно. Fixture-only skips имеют нулевой вес, но перечислены отдельно в аудите и не считаются измеренными исполнениями. Группировка fixtures остаётся прежней. Неизвестные истории тесты не исключаются из обнаружения или покрытия.

## Отдельные локальные замеры для Linux

`scripts/linux_test_placement.json` дополняет, но не заменяет официальный
снимок. В нём только целиком исполненные и прошедшие группы тестов, без
пропусков и ожидаемых падений. Поля source фиксируют публичный коммит и то
же дерево, на котором запускался локальный `PartitionRunner`, платформу,
архитектуру и Python. Указаны фактические секунды каждого теста; SHA-256
идентифицирует отчёт группы. Это не замер GitHub runner, не данные Intel
macOS и не свидетельство полного зелёного прогона.

Дополнение применяется только на Linux с той же архитектурой и версией
Python major/minor. Группа переносится из Light в Heavy только при точном
совпадении всех обнаруженных ID и сумме больше прежнего порога. При изменении
состава действует обычная история (неизвестные ID оставляют группу в Light).
Официальные Intel-оценки не меняются: новые Linux-группы распределяются
отдельно, а их секунды выводятся отдельным полем. Discovery, критерии успеха
и правила допуска merge не меняются. На draft или после красного Light
существующий workflow не запускает Heavy; перенесённые тесты проверяются
при полном допуске, а не удаляются.

Для сравнения планов используйте `--plan-only --plan-output /tmp/plan.json`
с одинаковыми `--tier` и `--shard-count`, затем повторите с
`--linux-placement ''`. Проверяйте непересекаемость Light и всех Heavy
шардов и равенство их объединения полному списку ID текущего дерева.

Чтобы повторить локальный замер группы, проверьте исходный коммит и дерево
из `source`, затем запустите весь указанный модуль, например
`python -m scripts.run_tests test_inventory_host_operations -v`. Для снимка
использовались исходные suite-узлы из discovery через `PartitionRunner`;
отчёт принимался, только если `wasSuccessful()`, все выбранные ID дали
время и не было пропусков или ожидаемых падений. Не используйте время
одного теста как вес непомеренной группы.
