# Перенос recovery дочерних форм на основную демо

Новый четвёртый сценарий `main_demo_browser_qa.mjs` использует только
`examples/demo`, OperationDraft и DraftDetails. Исходники конфигурации не меняются.

14 действий (весь набор: 4 сценария, 95 действий) проверяют:
- два независимых владельца и несохранённый текст в дочерней форме первого;
- запрет команд при приостановленном владельце;
- двойной click при задержанной доставке уже завершённого результата: одна команда,
  закрытие дочерней формы только после доставки, повторное открытие подготовленных данных;
- потерю ответа после фактического закрытия другой дочерней формы;
- отсутствие повторного Accept при инспекции, сохранение текста для копирования,
  блокировку неясного исхода и отсутствие изменений в SQLite.

Здесь не моделируется editable поле владельца: в основной демо оно read-only.
Raw draft проверяется в независимой дочерней форме. Все прежние sandbox,
source binding, network и deadline ограничения сохранены. Старый results harness
и его отдельная конфигурация пока не удаляются: перенос надо подтвердить реальным
Chromium-прогоном. Статические контракты и host-тесты не являются этим доказательством.
