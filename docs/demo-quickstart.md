# Мини-демо: создать базу и открыть редактор

Эта инструкция запускает исходное демо в локальной SQLite-базе Yadinassi.
Она не требует установленной 1С, Node или сети во время работы. Требуются
Python 3.10+ с установленными зависимостями проекта и исходники репозитория.
Для установки см. [README](../README.md#разработка).

## Первый запуск

Выполните из корня репозитория:

```console
python -m yadinassi --create-demo-db demo.sqlite --import-xml tests/fixtures/demo_cf/source
python -m yadinassi --ui --f demo.sqlite --open-browser
```

Первая команда создаёт новый файл. Вторая запускает локальный редактор и
открывает браузер. Если окно не открылось, перейдите по напечатанному локальному
URL. Без `--open-browser` браузер автоматически не запускается. Сеансовый URL
не пересылайте другим людям.

Для путей с пробелами используйте кавычки. В установленном Python-пакете
`python -m yadinassi` можно заменить на `yadinassi`: общий `--ui`
работает одинаково в пакете, исходниках и автономной сборке.
Пакет не содержит XML-исходники демо: `--import-xml` должен указывать на
`tests/fixtures/demo_cf/source` из соответствующего checkout репозитория.

Автономный бинарник принимает ту же команду создания, а редактор выбирается
первым аргументом `--ui`:

```console
yadinassi --create-demo-db demo.sqlite --import-xml /path/to/yadinassi/tests/fixtures/demo_cf/source
yadinassi --ui --f demo.sqlite --open-browser
```

На Windows используйте `yadinassi.exe`; на Linux/macOS для файла в текущем
каталоге обычно требуется `./yadinassi`. Релизный архив также не содержит
исходники демо. Старый бинарник без `--create-demo-db` нужно заменить сборкой,
включающей эту возможность.

## Первый сохранённый товар

База пустая: записи создаёт пользователь, готовые данные не подмешиваются.

1. Выберите **ВидыНоменклатуры** → **New record**. Введите `Товары` в Description
   и нажмите **Save changes**. Код назначится автоматически. Вернитесь в список
   через **Back to records**.
2. Выберите **Склады** и создайте `Основной склад`, оставив Code пустым.
   Сохраните и вернитесь в список. Аналогично можно создать `Резервный склад`.
3. В **Номенклатура** создайте `  Кабель USB-C  `. Выберите вид `Товары`, добавьте
   строку **Склады** через **Add row** и выберите склад. При желании добавьте
   вторую строку для резервного склада.
4. Нажмите **Save changes**. Исходные обработчики удалят пробелы по краям имени,
   проверят ссылки и строки. После успешного сохранения появится код.
5. Вернитесь в список и нажмите **Проверить карточку** у товара. Команда проверяет
   сохранённые данные, не изменяя их.
6. Закройте карточку и нажмите **Close database**. Запустите только команду
   редактора повторно. Откройте товар и проверьте имя, код, вид и склады.

Чтобы увидеть отказ исходного обработчика, попробуйте создать вид с именем
`АБ` или сохранить товар без вида/складов. Отказ сохраняет редактируемые поля,
но не записывает карточку. Исправьте данные либо выберите **Discard & return**.
Пометки удаления и дополнительные проверки описаны в
[документации исходного демо](demo-products.md).

## Повторный запуск и ошибки

- Повторно открывайте базу через `--f`. Не повторяйте команду создания.
- Существующий файл не перезаписывается. Для ещё одного чистого демо выберите
  новое имя файла. Старые kinds-only, directories-only и inactive базы не
  обновляются этой командой.
- Принимаются только точные 19 исходных XML/BSL-файлов текущего демо. Изменённый,
  неполный или посторонний набор отклоняется до создания файла. Нет режима
  «разрешить всё» для произвольной конфигурации.
- `--create-demo-db` требует `--import-xml` и не совмещается с `--create-db`,
  `--f`, исполнением BSL, `--inactive` или `--numbering-policy`. Нумерацию
  определяет существующий демо-профиль.
- При ошибке создания, особенно `outcome uncertain`, сохраните появившийся
  файл и SQLite journal. Не удаляйте их и не повторяйте запись автоматически:
  фиксация могла уже состояться.

## Что проверено этим срезом

CLI-тесты проверяют создание из исходников, точное сохранение всего архива,
три пустых справочника, защиту существующих файлов и старых профилей, отказ
неподходящему источнику, ошибки и неопределённый исход фиксации. Один сквозной
host-тест проходит создание БД → отказ короткому имени вида → вид и склад →
товар со ссылкой и строкой → проверка карточки → закрытие и повторное открытие.
Проверены вызов Python-модуля и исходный entrypoint упаковки из другого каталога.

Это не браузерный прогон, не проверка бинарника этого среза и не прохождение
всех 12 исходных сценариев на реальной 1С. Код редактора, исходные XML/BSL и
правила предметной области этим срезом не меняются. Границы локальной проекции,
включая лимиты выбора ссылок и строк, остаются прежними.
