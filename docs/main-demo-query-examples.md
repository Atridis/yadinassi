# Отчёты на одной основной демо

Все три примера используют `examples/demo`, ту же SQLite-базу, что интерфейс.
Отдельные Orders/Products/Categories-конфигурации для них не нужны.

```console
python -m yadinassi --f demo.sqlite examples/derived-document-report.bsl
python -m yadinassi --f demo.sqlite examples/document-query-report.bsl
python -m yadinassi --f demo.sqlite examples/query-membership-report.bsl
```

Базу сначала создают из основной демо, затем добавляют в интерфейсе или CLI
склады, виды номенклатуры, товары и поступления. Пустая база даёт пустой отчёт.
Сценарии не создают данные и не проводят документы.

- `derived-document-report`: номер и сумма строк каждого сохранённого поступления,
  в том числе непроведённого. У документа без строк сумма 0.
- `document-query-report`: склад, количество поступлений со строками и их сумма.
  Помеченные на удаление документы исключены. Используется временная таблица;
  строки не сохраняются в SQLite.
- `query-membership-report`: номер поступления и сумма каждой его строки от 10
  до 100 включительно. Состояние выбирается массивом перечислений (изначально
  `Draft`), товары с пометкой удаления исключены. Это фильтр атрибута State,
  а не признак проведения: он не равен Posted.

Это отчёты по сохранённым документам, не отчёты по движениям: для остатков и
оборотов используйте Stock в основной демо. Проверка
`test_main_demo_query_examples` исполняет настоящие файлы на основной базе,
включая пустую базу, переоткрытие, неизменность файла и отбор удалённых товаров.
Это проверка локального контракта, не свидетельство нового прогона на 1С.
