# Страницы списков записей

Host UI снимает полный ограниченный snapshot стандартных колонок справочника
или документа за один короткий read lease. После этого lease закрыт: ожидание
кликов браузера не удерживает SQLite-транзакцию и не блокирует запись.

Ограничения: до 8192 записей и 4 MiB текстовых summary-данных, страницы по 50.
Превышение означает отказ всего снимка, а не усечённый список, объявленный полным.
Общие backend-ограничения источника не расширяются. Пользовательские реквизиты
и табличные части не материализуются для просмотра списка.

Поиск без учёта регистра выполняется по уже проверенному detached snapshot:
код/наименование справочника или номер документа. Порядок фиксированным набором
полей: код/наименование либо дата/номер. Это семантика host UI, не обещание
региональной сортировки или динамического списка платформы 1С.

Внешние изменения видны после Refresh. Собственная запись заново снимает список,
сохраняя поиск, порядок и номер страницы, если он ещё существует. Открытые формы
и незаписанные черновики других форм не заменяются. Сохранение внутри form dispatch
проверяет свежий сохранённый объект; список снимается host-контроллером уже после
выхода из dispatch, без обхода admission fences.

Навигация и строки используют разные непрозрачные host-токены. Backend cursor
никогда не попадает в браузер. Смена страницы отзывает старые токены строк;
refresh/фильтр отзывает старые курсоры снимка. Счётчик ключей монотонный и ключи
не переиспользуются после очистки карты. При открытии записи её содержимое
всё равно читается заново из проверенного источника.
