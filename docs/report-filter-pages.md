# Страничный выбор фильтров складского отчёта

В настройках `BalanceAndTurnovers` выбор справочного фильтра поддерживает страницы по 32 записи, поиск по коду и описанию, точный код и явное обновление. Полный снимок ограничен 8192 записями / 4 MiB; превышение возвращает `snapshot_limit` без строк и без выдуманного общего количества. Точный код может сузить новый снимок.

Поиск нечувствителен к регистру (`casefold`) и работает по одному detached-снимку. Внешние изменения видны после Refresh. Поиск после точного кода возвращается ко всему справочнику. Точный код остаётся регистрозависимым точным сравнением, а не префиксом.

Каждый переход выдаёт новый билет выбора и новые непрозрачные варианты/курсоры. Старые варианты нельзя применить к новой странице или другому набору настроек. Никакие ключи справочника не передаются как права записи. Чтение вариантов и чтение самого отчёта остаются отдельными admitted-снимками с проверкой источника, схемы, базы и поколения.

Семантика исторического отчёта не приравнивается к редактору: новые варианты не включают помеченные записи, но ранее выбранная ссылка может оставаться фильтром исторических движений и отображаться как недоступная. Фактическая ссылка повторно проверяется при чтении отчёта. Отмена выбора сохраняет уже выбранные фильтры; пустая ссылка, все записи и выбранная ссылка остаются разными состояниями.

Этот блок не меняет пагинацию результата отчёта, лимиты его вычисления, разрешённые профили или исходники конфигурации.
