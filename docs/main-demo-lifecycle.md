# Lifecycle и общие модули основной демо

`examples/demo` включает управляемый модуль приложения и два общих модуля:

- `DemoTools` работает на клиенте и составляет информационный текст;
- `DemoService` работает на сервере и доступен через ServerCall;
- `ПриНачалеРаботыСистемы` вызывает DemoTools, который получает заголовок
  через DemoService, и выводит сообщение один раз при старте приложения.

При локальном запуске UI клиентский и серверный runtime остаются разделены:
вызов проходит через существующий invocation transport. Общие модули и lifecycle
имеют только memory-only family, без database_context. Обработчики исходных
справочников и документов сохраняют собственные, отдельно проверяемые права.
Никакого автоматического создания записей или открытия карточек при старте нет.

Источник расширен до 47 файлов; проекция для Designer теперь 46 файлов.
Обновление expected hashes не является свидетельством native-приёмки.
Результаты прежних прогона 1С и browser39 относятся к прежнему источнику.
Для нового источника требуется свежая проверка Designer, затем browser.

Форма **Обзор основной демо** (`DemoWelcome`) содержит кнопку открытия черновика:
она передаёт аргумент `4` по значению серверной `DemoService.Add`, получает серверное
сообщение и результат `5`, затем вызывает клиентскую `DemoTools.OpenOperation`.
Именно общий модуль вызывает OpenForm, открывая уже существующую OperationDraft.
Закрытие обзорной формы не завершает открытый черновик. Сценарий проверяется
через настоящий дочерний процесс в `test_main_demo_application_process`.

Отдельные application-host/business примеры пока не удалены: перед удалением
нужно завершить перенос их навигационных сценариев и соответствующего покрытия.
Это не повод сохранять их как рекомендуемые пользовательские базы.
