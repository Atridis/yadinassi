# Исполнение BSL через Python

`Interpreter()` и CLI используют единственный backend `python-direct`.
BSL разбирается в AST, который общий генератор переводит в Python.
Код вызывается в контексте конкретной точки входа: автономный скрипт,
динамический фрагмент, модуль приложения или обработчик. Ошибка подготовки
или исполнения не переключает программу на старый движок.

- `execute(text)` разбирает и выполняет исходник.
- `execute_program(ast)` использует переданное синтаксическое дерево.
- [`prepare` и `execute_prepared`](python-direct-prepared.md) позволяют
  подготовить исходник отдельно от исполнения.
- [`--emit-python`](emit-python.md) показывает Python-код плана без исполнения BSL.

Обычный `Interpreter()` не разрешает регистрацию Python-функций и типов.
Если приложение на Python намеренно расширяет язык, создайте интерпретатор
с `allow_extensions=True`. Это API для доверенного хоста, а не песочница
для исполнения недоверенного кода. База SQLite и переходы между клиентом
и сервером имеют отдельные контракты приложения; наличие базы само по себе
не включает Python-расширения.

Для обычного синтаксиса сначала используется [прямая трансляция](direct-codegen-defaults.md).
Если BSL и Python ведут себя по-разному, преобразование должно быть
ограничено нужной операцией и проверено тестом. Владение объектами, вызовы
Python-хоста и настоящие клиент-серверные переходы не следует путать
с проверками на каждой итерации обычного цикла.

Единый генератор не означает, что вся совместимость с 1С уже восстановлена.
См. [как проверять поведение на 1С](native-testing.md) и
[как сравнивать производительность](execution-layer-benchmarks.md).
