# Fixed Columns.Move measurement profile

`tree-columns-move-v1` registers the independently reviewed 28-case
[standalone observer](value-tree-columns-move-measurement.md). It does not
implement Columns.Move. No native measurement has run for this source yet.

## Closed acquisition and acceptance

The immutable registry binds one source SHA256, `tree_columns_move` case,
`native_1c_tree_columns_move_contract` decoder, 29 messages, unique stage/transport
schemas and `tree-columns-move` artifact namespace. `--tree-columns-move-suite`
is a literal runner flag; the host accepts only named fixed profiles and rejects
repeated profile arguments. New decoder imports are lazy; old staged inventories
do not need this new module. No dynamic source paths or profile dispatch input.

The existing Copy job ID, needs, permissions and dispatch exclusion are retained;
its literal fail-fast:false matrix now lists Copy, Sort and Columns.Move. The
aggregate result fails when any required entry fails. Fill remains unchanged.
Unknown/duplicate rows, mixed cases/artifacts and extra CLI flags are rejected.

Both native server and client must produce valid, identical captures with
source/module provenance and successful cleanup. Acquisition-shaped M records
can be decoded but **cannot establish availability**. Comparison requires cases
1 and 2 to succeed and exact complete output parity. Invalid observers, failed
server/client processes, missing/bad capture, nonquiet processes and bus cleanup
failure cannot export a successful artifact. Repeated artifact export rejects.

Original action exceptions are captured before nested helpers. Actual post-error
state, fresh identities and independently observed named/positional cells are
retained. No row/column preservation or rollback result is presumed.

Server module: 15583 bytes; generated client module: 19775 bytes. Current
unimplemented-interpreter server/client captures both contain 7480 bytes of
missing-method observations and fail the availability gate. These are local
synthetic execution results, not native answers.

All existing Fill/Copy/Sort observer bytes and generated client modules remain
identical. Existing decoder grammars, historical pins and full_suite.py are
unchanged (289493 LF / 294075 CRLF; 837-byte CRLF headroom). Runtime inventory
remains 78. No strict source/report/capture cap or security gate is relaxed.
UTF-8 reads and canonical LF synthetic fixtures are explicit; production still
rejects CRLF/hash-drift source bytes, independently of the Python host OS.

Native measurement and separate runtime work require later independent evidence.
Clear and last-column deletion guards are unchanged.
