# Вызовы между модулями в автономном запуске

Для обычного запуска BSL-файла через CLI разрешает связывать обычные функции из
файловых импортов один раз, при первом исполнении места вызова. Объявление
импорта по-прежнему инициализирует файл как раньше. Неисполненная ветка
не разрешает имена функций и не создаёт точку вызова.

При простых аргументах (имя или литерал) связывается экспортированная
клиентская функция со всеми переданными параметрами по значению, если
сгенерированная функция не замыкается на состояние или контекст модуля.
Результат связывания хранится только в конкретном запуске. На следующих
вызовах нет повторного обхода пространства импорта или открытия контекста
модуля; ошибка по-прежнему указывает на BSL-файл функции.

Импорты со ссылочными параметрами, внешними вызовами, динамическим
исполнением или зависимостью от состояния модуля идут через существующие
границы прямого движка. Это работает с параметром `--f` и без него.
Режим встраивания в Python, REPL и специальный запуск `--module-runtime`
не меняются. `--emit-python` показывает код автономного запуска, не читая
и не исполняя импортируемые файлы.

В автономном запуске генератор также не добавляет проверки живости к
обычным операторам, доступу к элементам коллекций и записи локального
состояния модуля. Выбор делается при генерации, без условной проверки
режима в цикле. Публикация состояния для динамического исполнения
остаётся; проверки на реальных границах вызова и переходах клиент–сервер
не отключаются.

Вызовы SQLite и управление транзакциями по-прежнему проходят через
проверки доступа и владельца транзакции. Само подключение БД не меняет
генерацию проверок для обычных операций BSL.
