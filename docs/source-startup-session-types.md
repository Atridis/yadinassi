# Запуск source-приложения и типы параметров сеанса

Source-host допускает сокращённые обработчики `BeforeStart()` и
`SessionParametersSetting()` без параметров. Обработчик всё равно выполняется;
это не пропуск инициализации. Варианты с Cancel/Names сохраняют прежнюю
семантику, включая отмену старта и ленивую инициализацию. Лишние параметры,
функция вместо процедуры и передача Cancel/Names по значению не принимаются.
Для strict configuration host прежняя сигнатура сеанса остаётся обязательной:
сокращённая форма включается отдельной source-only опцией компиляции.

В source-параметрах сеанса поддержаны UUID, ValueStorage, TypeDescription и
FixedArray, наряду со скалярами, FixedMap и FixedStructure. Допускаются явные
составные декларации до 16 альтернатив: неизвестная альтернатива отклоняет
декларацию целиком, а не исчезает. Квалификаторы скаляров сохраняются. Запись
не преобразует значение в другой тип, а отклонённая запись не заменяет прежнее.
Неиспользованная неподдержанная декларация сохраняется и даёт предметную ошибку
при обращении; значения по умолчанию не выдумываются.

Фиксированные коллекции проверяются рекурсивно: изменяемые вложенные объекты,
циклы и неподдержанные ссылки не принимаются. ValueStorage сохраняет собственный
неизменяемый снимок и возвращает независимые значения через Get. Учёт размера
снимков выполняется без Get/распаковки. Локальные бюджеты: 10000 узлов, глубина
коллекций 32 и 16 MiB расчётного удерживаемого объёма на значение; это ограничения
Yadinassi, не заявленные ограничения платформы. Сжатые снимки учитываются по
удерживаемому представлению, а не по объёму будущей распаковки.

Доступ остаётся только у серверного контекста своего живого source-приложения.
Это не выдача прав 1С, не ACL, не клиентский транспорт параметров и не активация
ссылок на объекты базы. Описания типов с такими ссылками пока отклоняются.
Полная интроспекция Type новых составных/объектных деклараций также не заявляется.

Контракт неизменяемых параметров и отсутствия defaults описан в
[официальном обзоре ограничений доступа](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Standards/Record-_and_field-level_access_restrictions/).
Тесты этого блока проверяют локальную реализацию, а не новый нативный прогон 1С.
