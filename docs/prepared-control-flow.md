# Подготовленные планы меток подпрограмм

Повторные вызовы подпрограммы используют immutable indexes её меток и вложенных
блоков. План принадлежит точному объекту AST подпрограммы, удерживает реальные
block references и не хранится в глобальном кэше по `id(list)`. При повторном
объявлении получается другой объект и другой план.

Публичный AST остаётся изменяемым. До аргументов каждого вызова выполняется
структурная проверка: identity и порядок statements, имена Label/Goto,
вложенность If/loop/Try и отдельные тела declarations. При изменении вся текущая
структура снова проходит label validation и новый план публикуется только после
успеха. Дополнительная проверка перед исполнением тела учитывает изменения из
host callback во время вычисления аргументов. Значения Literal, включая host
objects с полномочиями, не копируются, не сравниваются и не хэшируются.

Это оптимизация повторного построения indexes и разрешения переходов, а не
O(1) invalidation: структурный проход остаётся. Активные планы принадлежат task
execution context; nested calls, server activation и async suspension не
переносят их между задачами. Dynamic Execute использует собственный список
statements, поэтому не подхватывает labels вызывающей подпрограммы. Неизменённые
правила outward jumps и отказ перехода в неактивный блок сохраняются.

Произвольная Python-мутация AST во время уже исполняющегося отдельного statement
не объявляется атомарной. Контракт проверок охватывает entry в вызов/блок и
следующий вызов, а не перехватывает каждое присваивание host-кода.
